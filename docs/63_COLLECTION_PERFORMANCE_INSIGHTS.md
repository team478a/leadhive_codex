# 収集精度・速度の実績比較 実装記録

## 目的

実際の収集結果を見ながら、保存につながらない検索語や時間のかかる収集元を判断し、検索条件と運用を改善できるようにする。

## 集計

プロジェクト内のすべての収集ジョブを、収集元と検索語ごとに集計する。定期検索だけでなく、通常の検索・URL登録・CSV取込も同じ基準で比較できる。

| 指標 | 内容 |
| --- | --- |
| 実行 | 同じ収集元・検索語で行ったジョブ数 |
| 発見・保存 | 検索候補数と実際に営業候補として保存した数 |
| 保存率 | 保存 ÷ 発見 × 100 |
| 公式外率 | 公式サイト外として保存前に除外した候補 ÷ 発見 × 100 |
| 重複・エラー | 重複候補数と処理エラー数 |
| 平均時間 | 処理時間を記録したジョブの平均時間 |

発見数が0の割合は0%とする。処理時間が未記録のジョブは平均時間から除く。

## 画面とAPI

企業収集画面の「収集精度・速度の実績」で確認できる。保存率が低い検索語は見直し候補、公式外率が高い検索語はノイズが多い候補、平均時間が長い収集元は実行量や検索条件を調整する候補として扱える。

`GET /api/projects/{project_id}/collection-performance` はプロジェクトの参照権限を確認してから返す。

## 検証

複数ジョブを同じ検索語で作成し、保存率、公式外率、平均処理時間、重複・エラーを実PostgreSQLで確認した。
