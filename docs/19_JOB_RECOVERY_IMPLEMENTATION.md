# ジョブ自動回収 実装記録

## 目的

バックグラウンド処理中にワーカーが異常終了しても、ジョブが `running` のまま残り続けず、
別のワーカーが安全に処理を再開できるようにする。

## 実装

`operation_jobs`へ次の情報を追加した。

- `attempt_count`: 処理を確保した回数
- `worker_id`: 現在処理しているワーカーの識別子
- `lease_expires_at`: ワーカーが処理権を保持する期限

ワーカーはジョブ確保時と各処理単位の前後にリースを更新する。新しいワーカーはジョブ確保前に
期限切れを確認し、最大試行回数未満なら進捗カウンターを初期化して再キューイングする。
上限へ達したジョブは失敗として終了し、画面に理由を表示する。キャンセル要求済みなら再試行せず
キャンセルで終了する。

回収後に古いワーカーが復帰した場合、保持していた `worker_id` が一致しないため次の処理へ進まず終了する。
既定のリースは300秒で、外部API・Web解析の設定可能な最大タイムアウトより長くしている。

## 設定

| 変数 | 範囲 | 既定 | 内容 |
| --- | --- | --- | --- |
| `WORKER_LEASE_SECONDS` | 60〜3600 | 300 | 異常停止と判断するまでの秒数 |
| `WORKER_MAX_ATTEMPTS` | 1〜10 | 3 | 異常停止後を含む最大試行回数 |

処理単位がリース時間を超える設定にはしない。ネットワークタイムアウトを変更する場合は、リース時間も
十分長くする。

## プロセス監視

本番ではワーカーを常駐サービスとして登録し、異常終了時に再起動する。systemd向けの例を
`deploy/leadhive-worker.service.example`に用意した。配置先、実行ユーザー、環境ファイルのパスを
本番環境に合わせて変更してから使用する。

```bash
sudo systemctl enable --now leadhive-worker
sudo systemctl status leadhive-worker
journalctl -u leadhive-worker -f
```

## 検証

- リース期限切れジョブの再キューイング
- 最大試行回数到達時の失敗化
- 所有権を失った旧ワーカーの停止
- Alembic downgrade / upgrade / model差分確認
- バックエンド全テスト、Ruff、フロントエンド検証、ブラウザE2E

外部サービスへの失敗通知は次の運用改善候補とする。
