## 原因と修正

1. PCの11ケースではログイン・再読込の直後、まだ存在しないナビゲーションを閉じたメニューと誤認し、PCでは非表示の「メニュー」をクリックしてタイムアウトしていた。共通テスト操作はsidebarの表示を待ってから開閉の要否を判断する。

3. 送信時間設定の初期読み込みには破棄済みeffectの応答を無視する処理がなかった。StrictModeの重複読み込みなどで古い応答が遅れて返ると、編集・保存後の表示を上書きできるため、active guardを追加した。送信ルール・保存API・承認条件は変更しない。
