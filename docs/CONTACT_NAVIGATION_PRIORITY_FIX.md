# G1追跡: 明示的な問い合わせ窓口の探索優先順位

2026-10-09。基準 `c698e31b9af984e74da0b66a1b26b9bccfff278b`（PR #10 merge）。Branch `codex/contact-navigation-priority`。

## 問題と再現

20サイト検証で前回検出した1件へ今回は到達しなかった。保存済みHTMLを読み、以前の検出URLがトップの候補一覧に存在することを確認した。候補84のうち8番目だった。

従来の `navigation_links` は「お問い合わせ」と完全一致する直接リンクと、導入事例・サービス本文に「問い合わせ」「問合せ」等が含まれるリンクを同じ優先度100としていた。DOM順で個別サービスの相談ページが先になり、そこから子リンクを探索するため一般窓口へ到達する前に追加8ページの予算を消費した。

原因は少なくとも候補URLの消失ではなく、一般窓口と本文中の言及の優先度が同一だったこと。この対象はポータル形式であり、フォーム発見と営業対象への適合性を区別する。

## 修正

`contact_discovery.py` の順位付けだけ変更した。既存HINTSとリンク表示文言が完全一致（空白除去・小文字化）する直接窓口は120、本文中の部分一致は既存100、URLパス一致は既存90を維持する。

探索上限8ページ・深さ3・HTTP/robots/public URL/同一サイト制約は変更しない。子リンク探索、iframe、query保持、外部埋め込みの未確認状態、フォームDOM検出条件、営業可否、Human承認、送信機能も変更しない。一般窓口の発見は営業許可を意味しない。

## 同じ保存HTMLによる比較

ネットワーク接続とDNSを禁止したプロセスで、基準commitの純粋なnavigation処理と修正後を同じprivate cacheに適用した。cache外URLは未取得のまま扱い、HTMLや成功結果を合成していない。

| 指標 | Before | After |
|---|---:|---:|
| トップ候補数 | 84 | 84 |
| 以前検出した窓口の順位 | 8 | 1 |
| 追加8ページ内の探索要求候補になるか | いいえ | はい |
| 実際のフォーム検出増加 | null | null |

以前検出した窓口のHTMLはcacheにない。したがって到達候補改善までを確認したのであり、DOM検出が10→11へ増えたとは主張しない。cache外ページの子リンクが未知であるため、実サイト上の探索全体を完全再現したものではない。
