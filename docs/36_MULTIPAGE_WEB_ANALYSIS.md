# 重要ページの巡回解析 実装記録

## 目的

トップページだけでは不足する企業情報を、公式サイト内の重要な下層ページから補完する。

## 巡回対象

トップページのリンクから次のページを優先度順に最大4ページ選ぶ。

1. 問い合わせ
2. 会社概要・企業情報
3. サービス・事業内容
4. 採用情報

同一ドメインのHTTP / HTTPSページだけを対象とし、PDF、画像、ZIPなどは除外する。リダイレクト後に外部ドメインとなったページは解析結果へ取り込まない。

## 安全性と負荷制御

各ページに既存のSSRF防止、標準ポート制限、robots.txt、タイムアウト、HTML種別、最大サイズ制限を適用する。robots.txtの判定結果は同一オリジン内で再利用し、ページごとの不要な再取得を避ける。

下層ページの取得に失敗しても他ページの解析を継続し、トップページの取得失敗だけを企業解析全体の失敗として扱う。

## 情報統合

トップページで欠けている次の情報を下層ページから補完する。

- 会社名
- 電話、メール、問い合わせURL
- 住所、都道府県、市区町村
- SNS URL
- 事業概要
- AI判定へ渡すWeb本文

実際に解析したURLは`companies.scraped_urls`へ保存し、企業詳細画面に表示する。本文全体は既存どおり最大100,000文字に制限する。

## 検証

- 重要度順のページ発見と4ページ上限
- 外部リンクと非HTMLファイルの除外
- 複数ページからの連絡先、所在地、SNS、本文統合
- Migrationのdowngrade / upgradeとモデル差分検査
- 既存のSSRF、robots.txt、解析保護、重複判定の回帰テスト
