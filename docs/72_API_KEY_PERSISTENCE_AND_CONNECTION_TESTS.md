# APIキー保存状態・疎通テスト

## 修正した問題

`SETTINGS_ENCRYPTION_KEY`が未設定の場合、管理画面へ入力したAPIキーを暗号化できず、DBへ保存できなかった。運用設定画面だけでは暗号化保存の準備状況と保存結果が分かりにくかった。

## 実装内容

- 暗号化保存が利用可能か運用設定画面へ表示
- DBへの最終保存日時を表示
- 各APIキーを「画面で保存済み」「環境設定を使用中」「未設定」で表示
- 保存後にAPIから返された最新状態で画面を即時更新
- Serper、Google Places、OpenAI、gBizINFOの個別疎通テスト
- 認証失敗、利用上限、HTTPエラー、ネットワークエラーを区別して表示
- 疎通確認日時を画面へ表示
- APIキーをログ、APIレスポンス、疎通結果へ含めない

## 疎通テスト

- Serper：検索APIへ1件の確認リクエスト
- Google Places：Text Search（New）へ1件の確認リクエスト
- OpenAI：モデル一覧APIで認証を確認
- gBizINFO：法人検索APIへ1件の確認リクエスト

Serper、Google Places、gBizINFOは1回分のAPI利用として扱われる可能性があるため、画面で確認してから実行する。

## ローカル環境

暗号化キーは環境ごとに一度だけ生成し、`.env`の`SETTINGS_ENCRYPTION_KEY`へ設定する。DBへ暗号化保存した後にキーを変更すると復号できなくなるため、運用中のキーは安全にバックアップする。
