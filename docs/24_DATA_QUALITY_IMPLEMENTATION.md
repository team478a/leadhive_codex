# 企業データ品質管理 実装記録

## 目的

営業リストに含まれる情報欠損と古いWeb解析結果を可視化し、再解析が必要な企業をまとめて更新できる
ようにする。

## 品質指標

プロジェクトごとに次の件数を表示する。

- Webサイトなし
- 住所なし
- 電話なし
- メールなし
- 電話・メール・問い合わせフォームがすべてない企業
- Web解析失敗
- 指定日数を超えたWeb解析結果
- 再解析可能な企業

期限は1〜3,650日で指定でき、既定は90日。解析完了状態で `scraped_at` がない企業も期限切れとして扱う。

## 再解析

Webサイトがあり、解析失敗または期限切れの企業を古い順に最大100社選び、`web_analysis` の
バックグラウンドジョブへ登録する。再取得が必要なため `force=true` とする。

同じプロジェクトでWeb解析が待機中・実行中の場合は409を返し、重複実行を防ぐ。対象がない場合も
空のジョブを作らず409を返す。進捗、キャンセル、異常停止回収、失敗通知は既存ジョブ基盤を利用する。

## API

| Method | Path | 内容 |
| --- | --- | --- |
| GET | `/api/projects/{project_id}/data-quality?stale_days=90` | 品質集計 |
| POST | `/api/projects/{project_id}/data-quality/reanalyze` | 再解析ジョブ登録 |

再解析範囲は `failed`、`stale`、`failed_or_stale` から指定できる。すべて所有権確認の対象。

## 検証

- 欠損連絡先、解析失敗、90日超過の集計
- 対象企業だけを含む再解析ジョブ
- 強制再解析指定と100社上限
- 二重登録の拒否
- バックエンド全テスト、Ruff、typecheck、lint、build、デスクトップ・モバイルE2E
