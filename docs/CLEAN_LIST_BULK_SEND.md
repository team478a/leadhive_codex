# クリーニング済みリストの一括送信

サイドメニューの「送信の準備・実行」に、文面準備・Human承認・一括送信・結果確認の順で表示します。
承認済みの宛先・文面は同じ画面から1クリックでまとめて送信できます。
画面を開く・更新するだけでは予約・承認・送信しません。

## 利用手順

1. まとめサイトや営業NGを収集対象外・連絡禁止へ移す。
2. 「営業準備」で会社別の文面を用意する。
3. 「承認キュー」で人が宛先・文面を確認し、再認証して承認する。
4. 「送信の準備・実行」で「一括送信へ」を押し、送信を開始する。
5. 「承認キュー」「メール配信状況」で結果を確認する。

クリーニングは送信承認の代わりになりません。未承認・期限切れ・連絡可否が不明なもの、
対象外・営業NG、予約・試行済みの承認は対象外です。
同じ企業に複数の有効な承認がある場合も自動選択せず、承認キューで不要なものを取り消します。
確認画面・CAPTCHA・アダプターなど特殊フォームは従来の個別確認手順を使います。

## 制御と途中失敗

一覧のプレビューは読み取り専用です。実行時は既存の予約APIが権限、承認payload・期限、
営業NG、配信停止、重複などを再検査し、ワーカーも送信直前に再検査します。
この変更は承認を自動作成せず、送信停止設定を解除せず、共通の上限を変更しません。
メールは既存の予約上限（24時間500件・1時間60件）とSMTP上限、フォームは共通上限に従います。
メールは最大10000件、フォームは100件ずつ既存APIへ渡します。

両経路の予約は一つのDBトランザクションではありません。メールが成功し、フォームが失敗することがあります。
その場合は成功分を明示し、「未完了の予約を再試行」で同じ予約キーと同じpayloadを使います。
成功した予約群は再登録しません。接続エラー後に新しい予約キーを作り直しません。
画面を開き直した場合はDBの予約履歴から対象を再取得し、UNKNOWNを含む既存予約を除外します。
「予約完了」は送信成功や到達確認を意味しません。閲覧者には開始操作を許可しません。

## 検証範囲

隔離したAPI mock UI試験でDesktop/Mobile、両経路、ページを超える一括対象、途中失敗と予約キー再利用、
送信停止とviewerを確認します。オフライン試験はNG・掲載媒体・期限切れ・予約済み・曖昧な複数承認を確認します。
実企業への送信、本番データ変更、mainへのマージ、デプロイは行いません。
