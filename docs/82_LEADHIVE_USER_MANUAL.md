# LeadHive 利用マニュアル

対象: LeadHive Windows ローカル版<br>
更新日: 2026-10-03

LeadHiveは、営業先候補の収集、企業サイトの解析、優先順位付け、営業文面の作成、メール・問い合わせフォーム送信、追客管理を一つの画面で行うツールです。

このマニュアルは、パソコン操作に慣れていない方がインストール後の業務を始められる順番で説明します。最初に「1. 10分で試す」を実行し、必要になった機能だけ後半を参照してください。

初期提供は**収集・解析・企業管理・文面準備・Human承認まで**です。実メール・フォーム・SMTPテスト・Codex送信引渡しは停止します。以下の送信操作の章は機能の参考説明であり、初期提供での送信許可ではありません。送信停止を解除してよい状態と同一視しないでください。

初心者は`Open-QuickStart.cmd`または[収集・準備専用ガイド](G14_BEGINNER_QUICKSTART.md)から始めてください。

## 1. 10分で試す

APIキーやメール設定がなくても、企業サイトのURLまたはCSVがあれば試せます。

### 1-1. LeadHiveを起動する

1. 管理者から受け取った検証済み配布ZIPをOneDrive外の通常のフォルダーへ展開します。GitHubソースZIPは使用しません。
2. このマニュアルを再び開く場合は`Open-Manual.cmd`をダブルクリックします。
3. 初回は`Install-LeadHive.cmd`をダブルクリックします。
4. Docker Desktopが入っていない場合は、表示された利用条件を確認して同意します。
5. Windowsから管理者確認やWSL 2の有効化を求められたら許可します。
6. Windowsの再起動を求められた場合は、再起動後に`Install-LeadHive.cmd`をもう一度実行します。
7. メールアドレスと12文字以上のパスワードを設定します。
8. ブラウザが開いたら、作成したアカウントでログインします。

初回は必要なプログラムを取得するため数分かかることがあります。2回目以降は`Start-LeadHive.cmd`をダブルクリックします。

通常の接続先は `http://localhost:8787` です。8787が使用中だった場合は、インストーラーが8788～8797の空き番号を選びます。

### 1-2. プロジェクトを作る

1. 左メニューの「プロジェクト」を開きます。
2. 「新規作成」を押します。
3. プロジェクト名を入力します。例: `東京都の制作会社開拓`
4. ターゲットプロファイルを選びます。
5. 営業目的を入力します。例: `Webサイト改善の提案先を探す`
6. 都道府県と市区町村を選び、「保存する」を押します。

プロジェクトは、営業目的や担当チームごとの入れ物です。目的が異なる営業活動は別のプロジェクトに分けると管理しやすくなります。

### 1-3. 企業を登録する

1. 左メニューの「企業収集」を開きます。
2. 作成したプロジェクトを選びます。
3. 収集元で「URL」を選びます。
4. 企業サイトのURLを1行に1件入力します。
5. 「収集を開始」を押します。
6. 保存済み企業に追加されたら「未解析を解析」を押します。

CSVを使う場合は収集元で「CSV」を選び、UTF-8形式、最大5MB・1000行のファイルを指定します。プレビューを見ながら会社名、URL、電話、メール、住所の列を対応付けます。

### 1-4. 結果を確認する

1. 左メニューの「企業一覧」を開きます。
2. 対象企業の「詳細」を押します。
3. 会社情報、連絡先、問い合わせフォーム、SNS、営業状況を確認します。
4. 必要に応じて「営業対象」または「対象外」へ変更し、メモと次回対応日時を保存します。

AI判定を利用する場合は、管理者が先にOpenAI APIキーを設定します。設定後、「企業収集」で「未判定をAI判定」を押すと、ランク、点数、理由、推奨アプローチが追加されます。

## 2. 画面の見方

| 画面 | 主な用途 |
| --- | --- |
| ダッシュボード | 通知、収集結果、営業成果、バックグラウンド処理を確認 |
| プロジェクト | 営業目的、対象地域、利用メンバーを管理 |
| ターゲットプロファイル | 検索語、必須条件、除外条件、AI評価基準を管理 |
| 企業収集 | 検索API、URL、CSVから企業を登録し、Web解析とAI判定を実行 |
| 企業一覧 | 絞り込み、企業詳細、担当、追客、連絡禁止、文面、送信、案件を管理 |
| メール配信状況 | 送信待ち、送信済み、失敗したメールを確認 |
| 運用設定 | APIキー、フォーム送信者、SMTP、IMAPを管理。管理者だけに表示 |
| 使い方ガイド | 初回の3ステップをいつでも再表示 |

スマートフォンでは左上のメニューボタンから各画面を開きます。大量の企業確認、CSV取込、設定作業はパソコンの利用を推奨します。

## 3. アカウントと権限

公開サインアップはありません。最初の管理者アカウントは`Install-LeadHive.cmd`の途中で作成します。

| 権限 | できること |
| --- | --- |
| 管理者 | 全体サービス設定、SMTP・IMAP設定、通常の営業操作 |
| プロジェクト所有者 | プロジェクト編集、メンバー管理、すべての営業操作 |
| 編集者 | 企業収集、解析、企業情報・営業情報・文面・送信の操作 |
| 閲覧者 | プロジェクトと解析結果の閲覧。変更や送信は不可 |

### 追加ユーザーを作る

追加ユーザー作成は現在、管理画面にはありません。管理者がLeadHiveのフォルダーでPowerShellを開き、次を実行します。

```powershell
. .\scripts\windows\Common.ps1
Assert-Docker
Invoke-LeadHiveCompose exec api python -m app.cli user@example.com
```

画面の案内に従い、12文字以上のパスワードを2回入力します。旧版から更新した環境でコマンドが接続できない場合は、`Diagnose-LeadHive.cmd`で診断ファイルを作成して管理担当者へ渡してください。

作成しただけでは他の利用者のプロジェクトは見えません。プロジェクト所有者が次の操作を行います。

1. 「プロジェクト」で対象プロジェクトを探します。
2. 「メンバー」を押します。
3. 作成済みユーザーのメールアドレスを入力します。
4. 「編集者」または「閲覧者」を選んで保存します。

## 4. ターゲットとプロジェクトを設計する

### ターゲットプロファイル

ターゲットプロファイルは「どの企業を探し、どう評価するか」の共通設定です。標準プロファイルは直接変更せず、「複製」して案件専用の条件を作ります。

- 検索キーワード: 企業を探す語句
- 必須条件: 営業対象として必要な条件
- 除外条件: 対象外にする条件
- スコアリング: AI判定で重視する条件
- 既定地域: 新しいプロジェクトで使う候補地域

特定業種だけに通用する条件は、プロジェクト名やメモではなくターゲットプロファイルへまとめます。

### 地域

プロジェクト作成・編集時に都道府県を選ぶと、その都道府県の市区町村を選べます。市区町村を指定しない場合は都道府県全体、都道府県も指定しない場合は全国として扱います。

検索APIが返す住所表記には揺れがあるため、企業一覧でも地域を確認してください。

## 5. 企業を収集する

### 収集方法の選び方

| 収集元 | 向いている用途 | 必要な設定 |
| --- | --- | --- |
| URL | 既知の企業サイトを登録 | なし |
| CSV | 手元の営業リストを移行 | なし |
| Google検索 | 業種名や地域名から幅広く検索 | Serper APIキー |
| Google Maps | 店舗・事業所を地域検索 | Google Places APIキー |
| gBizINFO | 国内法人情報から検索 | gBizINFO APIトークン |

検索語は1行に1件入力します。最初は少ない件数で結果を確認してから増やしてください。同じドメインや法人番号は重複候補として扱われます。

### バックグラウンド処理

Google検索、Google Maps、gBizINFO、複数社のWeb解析、AI判定はバックグラウンドで処理されます。画面を閉じてもジョブはDBに残り、ワーカーが動いていれば処理を続けます。

- 「待機中」: 実行順を待っています。
- 「実行中」: 処理中です。
- 「完了」: 処理が終了しました。
- 「失敗」: エラー内容を確認し、原因を直して「再実行」します。
- 「中止」: 利用者が停止しました。必要なら再実行できます。

### 定期収集

Serper、Google Places、gBizINFOでは、現在の検索条件を定期収集テンプレートとして保存できます。実行間隔とプロジェクト企業上限を設定し、「今すぐ実行」「停止」「再開」で管理します。

テンプレート別成果と「収集精度・速度の実績」で、保存率、重複率、公式サイト以外の割合、平均処理時間を比較できます。保存率が低い検索語は具体化し、公式外が多い検索語は企業名や地域を追加してください。

## 6. 企業情報を確認・整備する

企業一覧ではランク、最低点数、地域、営業状況、収集元、キーワード、担当者、フォロー期限で絞り込めます。よく使う条件は保存フィルターとして登録できます。

企業詳細では次の情報を管理します。

- 会社名、住所、都道府県、市区町村、電話、メール
- Webサイト、問い合わせフォーム、SNS
- 先方担当者の氏名、部署、役職、連絡先、確認状態
- AI要約、強み、懸念、推奨アプローチ
- 社内担当者、営業状況、次回対応日時、メモ、活動履歴
- 案件名、段階、見込金額、次の対応、予定日

### 営業状況

`未確認 → 営業対象 → アプローチ済 → 返信あり → 商談 → 成約`を基本の流れとして使います。失注した場合は「失注」、対象にしない場合は「対象外」を選びます。

複数社を選択すると、営業状況と担当者を最大100社まで一括更新できます。

### 手動修正を保護する

会社名、住所、電話、メール、フォームURL、SNSなどを手動で直した場合は、項目下の「Web再解析から保護」を選びます。保護した項目は次回の自動解析で上書きされません。

### 重複企業

重複候補では、どちらの企業情報を残すかを確認して統合します。統合すると連絡先や活動履歴などが保存先企業へ集約されます。似た社名だけで判断せず、公式URL、法人番号、住所、電話を確認してください。

### 連絡禁止

相手からの拒否、配信停止、既存顧客、競合など、連絡してはいけない企業は「この企業への連絡を禁止」を選び、理由を保存します。連絡禁止と抑止リストはメール・フォーム送信の直前にも確認されます。

## 7. Form Intelligenceを使う

Form Intelligenceは企業サイトから問い合わせページを探し、フォーム項目、営業禁止表記、CAPTCHA、確認画面、通常送信への対応可否を事前に解析します。

1. 企業一覧で対象企業を選び、「フォーム解析」を押します。
2. バックグラウンド処理の完了を待ちます。
3. 企業詳細の「フォーム事前解析」を確認します。
4. 複数フォームが見つかった場合は、営業連絡に使うフォームを「優先フォーム」にします。
5. 誤った項目割り当ては標準マッピングと推奨値を直し、修正理由を保存します。

### フォーム状態

| 状態 | 意味と対応 |
| --- | --- |
| 未解析 | 「フォーム解析」を実行します。 |
| 送信準備完了 | 通常送信の候補です。送信前に内容を確認します。 |
| 要確認 | 入力項目、営業可否、JavaScript等を人が確認します。必要ならCodex支援を使います。 |
| 送信対象外 | 営業禁止表記などが検出されています。送信しません。 |
| 変更あり | 解析後にフォーム構造が変わりました。再解析します。 |
| 解析失敗 | URLやサイト状態を確認して再解析します。 |

営業可否は「許可」「禁止」「不明」で表示されます。「不明」のまま自動送信せず、企業の規約とフォームの説明を人が確認してください。

CAPTCHAを自動突破する機能はありません。JavaScriptで生成されるフォーム、iframe、Shadow DOM、ファイル添付などは通常送信の対象外になり、ブラウザまたはCodex支援へ回ります。

## 8. 営業文面を作る

企業詳細の営業文面欄で、メール用またはフォーム用の文面を作成します。

1. 送信経路を選びます。
2. AI生成を使う場合は、企業情報と営業目的を確認して生成します。
3. 件名と本文を編集します。
4. 誤情報、過度な表現、宛名、署名、連絡先を人が確認します。
5. 保存し、送信前の承認操作へ進みます。

よく使う文面はテンプレートとして保存できます。A/Bテストを使う場合は、同じ目的で複数の文面を用意し、返信率や商談率を比較します。

AIが生成した文章はそのまま送らず、企業サイトの事実と一致しているか確認してください。

## 9. メールを送る

メール送信には管理者によるSMTP設定とテスト送信の成功が必要です。

### 1社へ送る

1. 企業のメールアドレスと連絡禁止状態を確認します。
2. メール用文面を開きます。
3. 宛先、件名、本文を確認します。
4. 送信承認のチェックを入れて予約します。
5. 「メール配信状況」で送信結果を確認します。

予約した時点ではSMTPへ即時送信されない場合があります。ワーカーが24時間の送信上限とメール間隔を守って順番に処理します。

ローカル版のURLは受信者のPCから開けないため、`PUBLIC_APP_URL`がlocalhostのままではメール内の自動配信停止リンクを利用できません。ローカル運用中は配信停止の返信を確認して連絡禁止へ登録してください。受信者が開ける配信停止リンクが必要な場合は、HTTPSで公開したサーバー構成と公開URLの設定が必要です。

### 一括メールを送る

1. 企業一覧で対象企業を選択します。
2. メールテンプレート、キャンペーン名、必要なら追客日数を選びます。
3. 対象企業、文面、連絡禁止・送信済み企業の除外を確認します。
4. 承認チェックを入れ、「一括メールを予約」を押します。
5. キャンペーンの送信待ち、送信済み、失敗、返信、商談、成約を確認します。

キャンペーンは停止・再開できます。送信後の追客日数を指定すると、送信成功時に次回対応日が登録されます。

失敗したメールは原因と宛先を確認してから再予約します。同じ企業へ重複送信しないよう、活動履歴と送信履歴を確認してください。

## 10. 問い合わせフォームへ送る

フォーム送信は、対象企業、送信先、文面、解析結果を人が確認して承認した場合だけ実行します。

### 1社へ通常送信する

1. Form Intelligenceが「送信準備完了」であることを確認します。
2. フォーム用文面を開きます。
3. 「解析済みフォームを確認」で入力項目と送信先を確認します。
4. 会社名、氏名、メール、電話、本文、問い合わせ種別などを確認・修正します。
5. 承認チェックを入れ、「フォームを送信」を押します。

送信直前にフォーム構造と連絡可否を再確認します。サイトが変わっていた場合は送信せず「変更あり」となるため、再解析してください。

### 一括フォームDMを送る

1. 企業一覧で対象企業を選択します。
2. フォーム文面テンプレートを選び、「選択企業で一括DMを作成」を押します。
3. 送信済み、連絡禁止、フォームなし等の除外理由を確認します。
4. 対象件数と文面を確認して承認します。
5. 通常フォームを最大20社ずつ処理します。

必須項目不足、選択式項目、CAPTCHA、JavaScript、iframeなどがある企業は「Codex支援」に残ります。対象外の企業へLeadHiveが勝手に送信することはありません。

「結果不明・再送禁止」は、通信切断や完了確認不能、試行途中の停止などで受付結果を断定できない状態です。フォームを再送したりCodexへ送信を引き継いだりせず、相手側の受付結果を確認してください。別の文面・一括DMを作っても結果不明の会社/同一フォームへの通常再送は拒否されます。自動解除や再送許可は追加していません。

### Codex支援で送る

1. 「Codex支援フォームの作業キュー」を開きます。
2. 対象企業とフォームURLを確認します。
3. 「承認してCodexタスクをコピー」を押します。この確認が1件だけの最終送信承認になります。
4. コピーされた内容をCodexへ貼り付けて実行します。
5. CAPTCHAが出た場合は、Codexの案内に従って人が画面上で完了します。
6. 結果をLeadHiveで「送信済み」または「失敗」として記録します。

インストーラーはLeadHive Form Submit Skillを同じWindowsユーザーへ配置します。Codexに表示されない場合はCodexを再起動してください。

## 11. 返信と追客を管理する

SMTP送信後の返信を取り込む場合は、管理者がIMAPを設定します。一意に一致した送信元だけが企業または先方担当者へ自動で紐付きます。候補が複数ある返信は手動確認キューに残ります。

ダッシュボードと企業一覧では次を確認します。

- 本日または期限超過のフォロー
- 受信した返信と未処理キュー
- 営業アプローチキュー
- 担当者別の成果
- 送信方法・文面別の返信、商談、成約
- 案件パイプラインと見込金額

電話、メール、フォーム、SNS、商談の結果は活動履歴へ残し、次回対応日時を必ず設定すると追客漏れを防げます。

## 12. 管理者の初期設定

左メニューの「運用設定」は管理者だけに表示されます。

### APIキー

使う収集方法だけ設定します。URLとCSVだけならAPIキーは不要です。

1. 「APIキーの取得手順」で利用サービスを開きます。
2. 公式サイトでキーまたはトークンを取得します。
3. LeadHiveの該当欄へ直接貼り付けます。
4. 「全体設定を保存」を押します。
5. 状態が「画面で保存済み」になり、最終保存日時が更新されたことを確認します。
6. サービスごとの「接続をテスト」を実行します。

| サービス | 用途 | 注意 |
| --- | --- | --- |
| Serper | Google検索 | 確認リクエストも1回分の利用になる場合があります。 |
| Google Places | Google Maps検索 | Google Cloudの請求先、有効化、API制限を設定します。 |
| OpenAI | AI判定、文面生成、曖昧なフォーム項目の判定 | ChatGPT契約とは別のAPI契約です。 |
| gBizINFO | 国内法人情報検索 | 利用申請で発行されたトークンを使います。 |

APIキーは保存後に再表示されません。空欄のまま再保存すると既存値を維持します。「暗号化キーが未設定」と表示された場合は保存できないため、インストール状態を確認してください。

### フォーム送信者情報

会社名、担当者名、部署、メール、電話、住所などを保存します。通常フォームと一括フォームDMの初期値に使われます。相手へ表示される情報なので、実在する連絡先を設定してください。

### SMTP

メールサービスの案内に従い、SMTPホスト、ポート、ユーザー名、パスワード、送信元、STARTTLSを設定します。必要に応じて通常のログインパスワードではなく、アプリパスワードを発行します。

1. SMTP情報を入力して「SMTP設定を保存」を押します。
2. 「設定済み」と表示されたことを確認します。
   送信停止中は「メールを送らず接続確認」で、接続・暗号化・認証の結果を確認できます。変更後は先に保存してください。この確認ではメールを送らず、相手への到達や配信通知の接続確認も行いません。
3. 自分が受信できるアドレスをテスト送信先に入力します。
4. 「テストメールを送信」を押し、受信箱と迷惑メールを確認します。
5. 実運用前に24時間の送信上限とメール間隔を小さく設定します。

### IMAP

返信取込を使う場合は、IMAPホスト、ポート、ユーザー名、パスワード、メールボックス、SSL、確認間隔を設定します。「接続をテスト」が成功してから「自動取込を有効にする」を選びます。

## 13. 日常運用のおすすめ手順

### 毎日

1. `Start-LeadHive.cmd`で起動します。
2. ダッシュボードの未読通知、失敗処理、本日・期限超過のフォローを確認します。
3. 返信キューとメール配信状況を確認します。
4. 営業アプローチキューから対象企業へ対応し、結果と次回対応日時を記録します。
5. 実行中の収集・解析・送信がないことを確認し、必要なら`Stop-LeadHive.cmd`で停止します。

### 新しい営業施策を始めるとき

1. ターゲットプロファイルを複製して条件を整えます。
2. プロジェクトを作り、地域と営業目的を設定します。
3. 少数の企業を収集し、Web解析とAI判定の品質を確認します。
4. 除外条件と検索語を調整してから件数を増やします。
5. 連絡先、営業禁止、フォーム状態を人が確認します。
6. 少量のテスト送信から始め、結果を確認して拡大します。

### 毎週

1. 担当者別成果、検索語別の保存率、文面別成果を確認します。
2. 重複候補と未確認の連絡先を整理します。
3. 失敗ジョブ、送信失敗、手動確認中の返信を処理します。
4. `Backup-LeadHive.cmd`を実行し、バックアップを別の安全な場所にも保管します。

## 14. バックアップ、更新、復元

| ファイル | 用途 |
| --- | --- |
| `Open-Manual.cmd` | この利用マニュアルをメモ帳で開く |
| `Start-LeadHive.cmd` | 起動してブラウザを開く |
| `Stop-LeadHive.cmd` | 停止。データは残る |
| `Backup-LeadHive.cmd` | DBと暗号化キーを`backups`へ保存 |
| `Restore-LeadHive.cmd` | 最新または指定バックアップを確認付きで復元 |
| `Update-LeadHive.cmd` | 新版へDB更新を適用して再起動 |
| `Diagnose-LeadHive.cmd` | Docker、WSL、LeadHiveの診断ファイルを作成 |
| `Resume-LeadHive.cmd` | 保守後のworkerを履歴確認後に再開 |
| `Import-LeadHiveBackup.cmd` | 元PCを停止して新PCへ検証済みbackupを移行 |
| `Repair-LeadHiveInstance.cmd` | 検証可能な初回登録失敗を復旧 |

業務データはDockerボリューム、DBパスワードと暗号化キーはLeadHiveフォルダー直下の`.env.local`にあります。`.env.local`を失うと保存済みAPIキーやメールパスワードを復号できません。

### 更新前

1. `Backup-LeadHive.cmd`を実行します。
2. `backups`に同名の`.dump`、`.dump.env.local`、`.dump.identity.json`があることを確認します。
3. 新版ZIPを新しいフォルダーへ展開します。
4. 旧フォルダーの`.env.local`を新版フォルダー直下へコピーします。
5. `Update-LeadHive.cmd`を実行します。

### 復元

1. `Restore-LeadHive.cmd`をダブルクリックします。
2. 表示されたバックアップを確認します。
3. `RESTORE`と入力します。
4. 別の新規DBへの復元と内容検証が成功し、画面のURLが表示されるまで待ちます。元DBは残ります。
5. workerは停止したままです。配送履歴を確認して`Resume-LeadHive.cmd`を実行します。

別のバックアップを使う場合は、`.dump`を`Restore-LeadHive.cmd`へドラッグします。環境ID・キー・内容ハッシュが一致しない場合や、検証報告がない旧backupは停止します。
新PCへの移行は、元PCを停止してから`.dump`を`Import-LeadHiveBackup.cmd`へ渡します。通常インストールで別の環境IDを作らず、元のキーを保持してください。
未処理や失敗配送がある場合、Resumeは再開を拒否します。送信済みか分からないものはretryせず管理担当者へ相談してください。backup・更新・復元後のworker停止中は、定期収集も停止しています。

環境IDのない旧版は、元の設定を保持して`Adopt-LeadHive.cmd`で引き継いでから更新します。[Windows導入ガイド](73_WINDOWS_LOCAL_INSTALLER.md)の手順に従ってください。

## 15. 困ったとき

| 症状 | 確認すること |
| --- | --- |
| 画面が開かない | Docker Desktopを起動し、`Start-LeadHive.cmd`を再実行します。 |
| Dockerのsocket、Inference、Secrets Engineエラー | Docker Desktopを完全終了し、Windowsを再起動してから再実行します。 |
| ログインできない | インストール時のメール、12文字以上のパスワード、英字の大文字小文字を確認します。 |
| APIキーが保存されない | 運用設定の「暗号化保存を利用できます」を確認し、保存後の状態と時刻を確認します。 |
| API接続テストが失敗する | キー、利用申請、請求先、利用上限、API制限、インターネット接続を確認します。 |
| 収集が進まない | ダッシュボードのバックグラウンド処理を確認し、失敗なら原因表示後に再実行します。 |
| AI判定できない | OpenAI APIキー、API残高、モデル名、接続テストを確認します。 |
| SMTPテストが失敗する | ホスト、ポート、STARTTLS、ユーザー名、アプリパスワード、送信元制限を確認します。 |
| メールが送信待ちのまま | キャンペーン停止、24時間上限、メール間隔、ワーカー状態を確認します。 |
| フォームを送信できない | Form Intelligenceの状態、営業可否、必須項目、CAPTCHA、フォーム変更を確認します。 |
| Codex支援Skillが見えない | 同じWindowsユーザーでCodexを再起動します。必要なら`Update-LeadHive.cmd`を実行します。 |
| データを復旧したい | 先に現在のフォルダーを残し、`Restore-LeadHive.cmd`でバックアップを選びます。 |

解決しない場合は`Diagnose-LeadHive.cmd`を実行し、`diagnostics`フォルダーの最新ファイルを管理担当者へ渡してください。診断ファイルにはAPIキー、メールパスワード、企業データを出力しません。

Docker Desktopの「Factory reset」はDockerボリュームを削除する可能性があります。バックアップを確保した最後の手段として扱ってください。

## 16. 安全に使うための確認事項

- APIキー、`.env.local`、SMTP・IMAPパスワードをチャット、メール、GitHubへ貼り付けない。
- 連絡禁止、配信停止、営業禁止表記がある相手へ送らない。
- メールとフォームは宛先、本文、送信先を確認してから承認する。
- AI文面とAI判定は人が確認し、事実と異なる内容を修正する。
- CAPTCHAを回避しない。表示された場合は人が正規の画面で対応する。
- 初回は少量で試し、送信上限と間隔を控えめに設定する。
- 個人情報と営業活動データは自社の規程と適用法令に従って管理する。
- アップデート、PC移行、Dockerの修復前にバックアップする。

## 17. 現在の制限

- 追加ユーザーは管理画面では作成できず、管理者によるCLI操作が必要です。
- LeadHiveは同じPCの`127.0.0.1`だけで開くローカル構成です。他のPCから同時利用するには別途サーバー構成が必要です。
- ローカルURLはメール受信者から開けないため、外部公開なしでは自動配信停止リンクを利用できません。
- JavaScript生成、iframe、Shadow DOM、ファイル添付のフォームは通常送信に対応しない場合があります。
- CAPTCHAは自動処理しません。
- 外部サイトの仕様変更により、収集・解析・フォーム送信が一時的に失敗する場合があります。
- Phase 6の業種別100社＋100社の実データ検証は、利用者とAPIキーを使う別作業です。

### 復元・別PC移行後の認証と承認

バックアップに含まれたログインsession、再認証challenge、Agent credential、未処理・承認済みApprovalRequestは復元時に失効します。再ログインし、Agentを利用する場合は管理者が既存のcredential発行APIで再発行してください（Agent管理UIは未実装）。営業提案は再作成してHumanが再承認します。過去の文面・承認者・承認日時・監査履歴は保存されます。workerは別途確認して再開するまで停止したままです。

### 収集専用運用（G1.3）

配布の初期設定は外部送信停止です。収集・解析・企業管理・文面準備・Human承認は利用できますが、メール・フォーム・SMTPテスト・Codex送信支援は実行できません。画面上部で停止状態を確認できます。

停止するには`Stop-LeadHiveOutbound.cmd`を実行してください。サービスを停止・再作成するため一時的に画面が切れ、workerは停止します。その後`Resume-LeadHive.cmd`で確認すると、送信停止を保持したまま収集・解析workerを再開できます。古い配送待ちは削除・自動再送されません。

環境ファイルの編集だけでは稼働中processに反映されません。別PC・古いcontainer・コピー済みCodexタスクの停止は別途確認してください。初期提供では送信停止を解除しません。

### 会社別メールの一括承認と送信予約

「承認キュー」で、準備済みの会社別メールを承認待ちに追加できます。「このページの文面をすべて表示」で内容を確認し、対象を選択してログインパスワードで一括承認します。承認だけでは送信しません。

承認済みの対象に、予約名・24時間上限・1時間上限を設定して送信予約します。初期状態は実行無効です。停止・再開・未実行の取消も同じ画面で操作できます。承認は最大24時間で失効するため、月間運用でも日々の対象を新しく承認します。実行中のSMTP通信は取消できません。

「SMTP受付済み」は相手への到達を保証しません。「結果不明・要確認」は再送せず、SMTP提供元の履歴を確認してください。詳しい手順・制限は [83_APPROVED_BULK_EMAIL_FOUNDATION.md](83_APPROVED_BULK_EMAIL_FOUNDATION.md) を参照してください。

## 配信結果と安全停止

「メール配信状況」の「配信結果と安全停止」で到達通知、不達、苦情、配信停止を確認します。サービスの履歴を人が確認した場合は「確認済みの配信結果を登録」でメールを選んで登録できます。恒久不達・苦情・配信停止はそのメール宛先を連絡禁止にします。通常のSMTP設定だけでは到達通知を自動取得できず、サービス固有の通知接続が必要です。

異常を検出するとプロジェクトの予約を一時停止します。停止理由と履歴を確認した所有者だけが、パスワードで再認証して安全停止を解除できます。解除後も連絡禁止と結果不明は残り、予約は別途再開する必要があります。詳しくは [84_EMAIL_FEEDBACK_AND_SAFETY_STOP.md](84_EMAIL_FEEDBACK_AND_SAFETY_STOP.md) を参照してください。
