# キーワードによるまとめページ除外

基準main: `302d8db921b41dcba7b2197f88a292b36c94c605`。
PR #93の既知4媒体ドメイン追加とは独立した、未知ドメインにも適用するページ単位の判定。

## 判定

検索結果のタイトルから、以下の組み合わせを検出する。

- おすすめ / オススメ / お勧め / 厳選 / 比較 / ランキング / 人気 ＋ 数字○選
- おすすめ / オススメ / 厳選 / 比較 / ランキング ＋ 会社・企業・業者○社
- 周辺 / 近郊 / エリア別 ＋ 一覧・ランキング
- おすすめ / 人気 / 厳選等 ＋ ランキング
- 比較・口コミ・評判 ＋ ランキング、まとめサイト、比較サイト
- おすすめ / 厳選 ＋ 編集部・まとめ記事

全角数字も対象。地域・業種の固定リストに依存しない。
「店舗一覧」「会社一覧」「ブログ」「求人」だけでは一律除外しない。
当社・弊社・自社・当店・当院、おすすめプラン・メニュー、支援・導入・対応実績、
比較サイト制作・ランキング改善等の自社提供を示すタイトルは保守的に保持する。
不明瞭な記事は従来どおり暫定候補として保持し、後段のWeb解析で確認する。

明瞭なまとめページはRawの分類 `ARTICLE` / 理由 `AGGREGATION_TITLE`、
取込結果 `NON_COMPANY_SOURCE` として残し、Companyへ取り込まない。
通常収集・fair-v1の双方で目標件数枠を消費しない。
同じドメインの公式トップまで自動禁止することはない。
企業による記事発信と企業自体の適否を区別する。

Web解析でも共通のタイトル判定を使う。記事ページを取得した際の既存の同一サイトトップ再探索は維持する。
問い合わせフォームの既存例外・営業NG・承認・送信条件は変更しない。
保存済みCompany、Raw、人間の判定を再分類・削除する処理は追加しない。
検索API呼出しや追加検索は増やさない。

- 通常 / fairの両方でRaw保持・枠非消費・同一ドメイン公式トップ取込を確認。
- 関連Backend試験142件成功、private Rawの2件は入力未提供でスキップ。

- 外部検索・実サイトアクセス・AI・承認・送信・本番データ変更なし。

集計: `docs/results/summary-keyword-offline-2026-10-12.json`。
入力は `backend/offline_tests/test_summary_keywords.py` の合成ケースで、実データのHuman適合率ではない。
Human precisionはnull。タイトルの省略・表記差、例外を含むまとめ記事は取りこぼしうる。
運用でのOK/NGを用いて誤除外・取りこぼしを評価する。本番未反映。

## 反映

DB変更・Migration・UI変更なし。マージ後はAPIとcollection-workerの更新が必要。
本変更は固定ルールであり、任意の単語を入力する管理UIの追加ではない。
ドメイン全体を除外したい場合は、既存の人間確認付き掲載媒体登録を使う。

初回の全Backend CIでは、旧仕様の「会社比較13選」7記事を保持するruntime再現試験4件が失敗した。
強いまとめタイトルを除外する今回の仕様へ期待値を更新し、一般的な企業情報記事7件は
引き続き保持する独立の対照ケースを追加した。Raw20件・通常/fair双方・未知求人の暫定保持を維持する。

最新main `03a0dee54e9d82a7c6480accedf0bd608d51d13e`（PR #93/#94統合）をmergeして整合。
同じテストファイル末尾への追加が競合したため、既知媒体の境界・枠非消費テストと、
未知まとめページ・公式トップ保持テストを両方残した。履歴の書換え・force pushなし。
統合後の関連Backend + 全offline suiteは273成功、private Raw未提供の2件スキップ。
変更範囲mypy、Ruff、format、API import、diff check成功。
