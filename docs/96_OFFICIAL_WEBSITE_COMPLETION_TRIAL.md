# 公式サイト補完・10店舗の試行結果

## 結果

2026-10-05、既存の姫路市100店舗プロジェクトで、公式サイトURL未登録85店舗から店舗名の昇順で先頭10店舗を調査した。無作為抽出ではなく、チェーン店舗を複数含むため、この比率を残り78店舗や月10,000件の処理能力へ外挿しない。

- 調査10店舗、公式サイトを確認・登録7店舗、独自サイトを確認できず未登録のまま3店舗。
- 全体のURL登録数は15 → 22、未登録数は85 → 78。
- 登録7店舗を既存Form Intelligence Serviceで再解析。processed=7 / success=7 / failed=0 / job status=completed。ここでsuccessは非ERRORの解析結果が保存されたという意味で、フォーム発見・営業許可・送信成功ではない。
- 再解析した7店舗の分類はCAPTCHA 5、要確認1、フォーム未発見1。新たな自動送信候補は0。
- メール送信・フォーム送信・承認済みフォーム予約はすべて0件。workerは停止を維持。

## 同一店舗の確認方法

元データのaddressは「兵庫県姫路市」だけだった。この住所だけで同一店舗と判断せず、各レコードのreference_urlにある元のHotPepper店舗ページから番地・店舗名を確認し、公式サイト記載と比較した。

確認に使用した公式情報：

- [etto店舗アクセス](https://etto-hs.net/access/)：2店舗の名称・番地を元の店舗ページと照合。
- Agu公式の[act店舗情報](https://agu-hair.com/salon/1422/)、[village店舗情報](https://agu-hair.com/salon/6764/)、[vision店舗情報](https://agu-hair.com/salon/431/)：名称・番地を照合。後者2店舗は予約リンク先の元店舗IDも一致。これらは公式の開店記事であり、現行情報を網羅する店舗マスターとは区別する。
- [Asobi Hair lab公式サイト](https://asobi-hairlab.com/)：店舗名と所在地を照合。類似名の東京都の別サイトは除外。
- [BANG RARA公式サイト](https://bangrara.com/)：店舗名・所在地・予約リンク先の元店舗IDを照合。

未登録3店舗について「公式サイトが存在しない」とは断定しない。今回の検索では独自サイトを確認できなかった。1店舗は公式SNSへの参照が見つかったが、フォーム解析対象のwebsite_urlへSNSや予約ポータルを代入していない。別の1店舗では同名の別店舗候補と住所が異なったため、そのサイトを登録しなかった。

## 更新の範囲と追跡

利用中のローカルDBのみ、確認済み7店舗のwebsite_urlとdomainを既存canonicalize_urlで登録。新規企業の追加やdomainを使った店舗統合は行っていない。Company ID・location_key・reference_url・company_name・addressは100店舗すべて維持。残り93店舗のwebsite_url / domainも変更していない。

各登録と同じtransactionで既存Activityへnoteを追加し、日時、変更前後のURL、元参照URL、公式根拠URL、照合住所、確認方法を記録した。「Human承認済み」や「営業許可済み」として記録していない。住所・電話・SNS・連絡先・手動保護項目は上書きしていない。

既存の企業編集APIはwebsite_url / domainを受け付けないため、今回は利用者指示による一度限りのローカル補完処理を使用した。これは一般ユーザーが画面で公式サイト補完できる機能の実装ではない。

## 再解析結果の意味

登録7店舗は4ドメインに属する。うち2店舗と3店舗はそれぞれ共通問い合わせフォームへ到達し、CAPTCHAを検出した。共通宛先の重複防止も維持され、店舗ごとの独立した送信先として扱っていない。

別の1店舗はファイル入力を含むフォームのため、既存互換性判定によりREVIEW_REQUIRED。添付の必須性・必要な入力・通常経路での対応可否は追加確認が必要で、Codex支援タスクは起動していない。最後の1店舗は既存探索範囲内でフォーム未発見。電話・予約サービスの存在は営業DMフォームの存在を意味しない。

プロフィールのsales_contact_status=ALLOWEDは既存ルールが解析範囲で禁止表記を検出しなかった場合の分類であり、相手からの営業同意や送信承認ではない。最終判断には既存evaluate_contact_permissionと承認・送信guardを使用する。

全100店舗の保存済み集計：

|---|---:|---:|
| 構造上の候補 | 2 | 2 |
| CAPTCHA | 1 | 6 |
| 要確認 | 1 | 2 |
| 解析エラー | 91 | 84 |
| フォーム未発見 | 5 | 6 |

| 最終連絡制御 UNCERTAIN | 96 | 91 |

補完後ERROR 84の内訳はURL未登録78と、今回再取得しなかった既存6店舗。PROHIBITED 9は共有宛先による制限で、営業禁止文言を9店舗で検出したという意味ではない。候補2は従来から存在する共通宛先で、最終連絡制御は許可されていない。

## 稼働・検証

- 再解析は既存Service / SafeFetcherを使用。GETのみ、AI OFF、既存robots・危険URL制御を維持し、店舗間に2秒の待機。Serper / Google Places / AI APIのキーは使用していない。

- API health / database=ok。企業100件、プロフィール111件。古い仮URLプロフィールは削除せず、既存Serviceの履歴管理を維持。
- Alembic headはfae47ac5e861のまま。コード・Schema・Migration・送信flag・配布パッケージ変更なし。コード変更がないため、今回の検証は実DBの件数・保存結果・既存一覧Service・API health・送信件数不変の確認に限定。
- outbound / human-approved-form / legacy-form / agent flagsはすべてOFF。worker停止の原因調査と再開は本試行の範囲外。
