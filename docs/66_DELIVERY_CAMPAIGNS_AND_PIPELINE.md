# メールキャンペーン・送信運用 実装記録

## 目的

確認済みのメール文面を複数企業へ予約送信し、停止・再開、配信停止、成果、追客までを一つの運用単位で管理する。

## 操作

企業一覧で企業を選択し、メール文面テンプレート、キャンペーン名、送信後の追客日数を指定する。対象、文面、除外条件を確認して承認すると、企業ごとの送信予約と承認履歴を作成する。外部SMTP送信は既存ワーカーが日次上限と送信間隔を守って処理する。

キャンペーンを停止すると、未送信の予約は保持したままワーカーが送信対象から外す。再開すると同じ予約を送信待ちへ戻す。送信済み、失敗、返信、商談、成約の件数を一覧で確認できる。

送信後の追客日数を指定した場合は、送信成功時に企業の次回対応日を自動登録する。失敗送信は既存のメール再送フローで、内容を確認してから再予約する。

## 配信停止

メール本文には `PUBLIC_APP_URL` が設定されている場合に配信停止リンクを付与する。リンクを開くと対象企業を連絡禁止にし、抑止リストへ記録する。以後、その企業をメール・フォームの送信対象にしない。

本番では `PUBLIC_APP_URL` にHTTPSで公開したアプリケーションURLを設定する。

## フォームDMの補完

一括フォームDMは承認後にバックグラウンドジョブへ登録され、ワーカーが最大20社を処理する。画面を閉じても進捗・失敗・中止状態を確認できる。予期しない失敗になった項目は、確認のうえ再試行待ちへ戻せる。必須入力やCAPTCHAなど自動対応できない項目はCodex支援フォームの作業キューに表示し、フォームを開く、作業開始を記録する、送信済み・失敗を記録する操作を行える。外部フォームの最終送信は担当者が画面で確認する。

## 案件パイプライン

企業ごとの案件に加え、プロジェクト全体で段階別件数、失注・受注を除く見込金額、案件ごとの次の対応と予定日を確認できる。

## API

- `GET` / `POST /api/projects/{project_id}/email-campaigns`
- `POST /api/email-campaigns/{campaign_id}/pause`
- `POST /api/email-campaigns/{campaign_id}/resume`
- `POST /api/public/unsubscribe/{token}`
- `GET /api/projects/{project_id}/form-codex-queue`
- `POST /api/form-delivery-batch-items/{item_id}/retry`
- `GET /api/projects/{project_id}/deal-pipeline`

## 検証

キャンペーンの承認、停止・再開、ワーカーによる送信と追客日登録、配信停止、フォーム失敗の再キュー、案件パイプラインを実PostgreSQLで確認する。
