# 担当者向け：入力・結果記録の運用ガイド

対象：収集した営業候補を担当者が操作し、入力できた／止まった理由を蓄積する運用。
この手順では送信しません。クラウド版・ローカル版で同じ画面を利用します。

## 開始前（管理者）

- 利用者をプロジェクトの編集者として登録する。閲覧者は結果を記録できません。
- 検索に使うAPIと会社名・担当者名・連絡先を運用設定で登録する。キーを担当者へ配らない。
- 入力を試す場合だけ、入力専用機能とWindows用PCパッケージを準備する。外部送信OFFは維持する。
- プロジェクト、提案内容、使ってよい入力情報を担当者へ伝える。予算等を推測して埋めない。
- スマートフォンは候補・結果確認用。PCランナーはWindows PCで実行する。

## 日々の操作

1. メニュー「担当者の作業ガイド」を開き、作業するプロジェクトを選ぶ。
2. 新しい候補が必要なら「企業収集へ」。キーワード・都道府県・目標件数・検索回数上限を設定する。検索には費用が発生する場合があります。登録済み候補なら飛ばす。
3. 「企業一覧へ」から会社の「詳細」を開く。問い合わせ先がなければ既存のWeb解析・フォーム探索を使う。解析中・未確認を成功扱いしない。
4. 営業禁止表示や連絡禁止を確認したら、理由と根拠URLを記録して「営業NGリストへ移す」。入力・送信しない。
5. 入力専用パネルでフォームと入力内容を確認する。任意項目は空欄でよい。必須の選択肢・予算・同意が判断できなければ停止する。
6. PCで入力を試すか、人が元フォームで入力まで確認する。確認・送信ボタンを押さない。
7. 結果を保存し、企業詳細を閉じて次の候補へ進む。止まった企業をその場で何度も再試行しない。

## PC入力と結果の戻し方

- 必要なら「未送信のPC結果をLeadHiveへ自動で戻す」を選ぶ（初期状態は未選択）。
- 「PC入力専用の依頼を保存」でタスクJSONをダウンロードする。有効期間は15分。
- 専用パッケージの `Start-Live-Input.cmd` を起動し、タスクJSONを選ぶ。
- 自分が利用するLeadHiveのHTTPS URLを確認して入力し、入力のみの確認に `INPUT` と入力する。
- 終了後、LeadHiveの「PC結果を確認」を押す。自動転送しない場合・転送失敗時は「PCの未送信結果JSON」から結果JSONを取り込む。
- PCの結果JSONはパッケージ内 `frontend/test-results/live-input-runner` に保存される。
- タスクには入力内容・短期接続トークンが含まれるため、メールや共有チャットへ貼らない。結果ファイルとタスクファイルを取り違えない。
- 期限切れなら旧依頼を取り消し、画面から新しい依頼を作る。ファイルの期限やURLを書き換えない。

## 人が操作した結果の記録

企業詳細の「入力を試した結果を残す」で、確認したフォームURLと結果を選択。
「入力できなかった」なら理由と確認メモを入力し、「未送信の入力結果を記録」を押す。
PCの結果が既に保存されていれば同じ結果を手動で重ねて保存しない。

| 状況 | 対応 |
|---|---|
| 営業禁止 | 営業NG登録し、次へ |
| 必須項目不明 | 項目名と停止理由を記録し、次へ |
| 任意の選択・チェックで停止 | 必須か任意かと画面の状態を記録。架空の値や同意で進めない |
| CAPTCHA | 回避せず停止・記録 |
| ページエラー・動的画面・iframe | URLと停止箇所を記録し、次へ |
| 入力機能が無効 | 管理者へ連絡。送信設定を解除しない |
| 結果転送失敗 | 結果JSONを取り込む。フォーム入力をやり直す必要はない |
| 実際の送信結果がUNKNOWN | 再送せず管理者へ。入力試行の結果とは別の状態 |

## フィードバックの書き方

「会社／フォームURL、操作した日時、止まった項目、選択した理由、期待した動作」を記録。
例：「任意の電話番号を空欄にした。予算の必須選択で停止。OEM提携のため該当する選択肢がない」。
パスワード・APIキー・入力した個人情報をメモやスクリーンショットへ残さない。
同じ理由を定期的に集計し、頻度の高い問題から改善する。記録しただけでAIが自動学習する機能ではありません。

## 送信開始は別工程

入力成功は営業許可・Human承認・送信成功ではありません。
実送信する際は対象・送信先・文章を人が承認し、既存の送信条件を満たす必要があります。
このUI整理では承認・送信・NG判定の安全制御を変更していません。
