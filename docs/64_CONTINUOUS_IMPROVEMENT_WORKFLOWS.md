# 継続改善ワークフロー 実装記録

## 目的

実運用で得た判定・送信・商談の結果を、次の収集条件、AI判定、営業文面の改善へつなげる。あわせて商談後の案件状況を企業単位で管理する。

## AI判定レビュー

企業詳細でAI判定を「正しい」または「誤り」として理由付きで記録できる。同じ企業へのレビューは最新の内容で更新される。企業収集画面では検索語ごとのレビュー数、正しい件数、精度を確認できるため、精度が低い検索語をターゲットプロファイル見直しの候補にできる。

## 収集の改善提案

収集精度・速度の実績は、保存率が低い検索語、公式外率が高い検索語、処理時間が長い収集元を明示する。AI判定レビュー精度と併せて、ノイズの多い検索語と営業適性の低い検索語を区別して改善できる。

## 文面A/Bテスト

同じプロジェクト・同じ送信種別のテンプレート2案でテストを作成する。企業IDからA案・B案を均等に決め、現在の営業文面へ適用する。適用した文面が送信完了になると、送信、返信、商談、成約、返信率を案ごとに集計する。送信前の承認と既存の配信制限は維持する。

## 案件管理

企業ごとに案件名、段階、見込金額、受注見込日、担当者、次の対応、失注理由を管理する。段階は見込み、提案、交渉、受注、失注。案件の作成・更新・削除はプロジェクト編集権限に従う。

## gBizINFO収集

収集元にgBizINFOを追加した。公式REST APIのトークンを `GBIZINFO_API_TOKEN` へ設定すると、キーワードと地域で法人候補を収集できる。トークンは画面・ログ・APIレスポンスへ出力しない。gBizINFOは法人基本情報を提供する公式APIであり、外部APIの利用申請とトークンが必要である。[gBizINFO APIの案内](https://content.info.gbiz.go.jp/api/index.html)

## 検証

- AIレビュー保存と検索語別精度集計
- 案件の作成と一覧
- A/Bテストの作成、均等割当、成果集計
- gBizINFOを収集元として扱う検索ジョブ
- DB Migration整合、Ruff、フロントエンド lint・本番ビルド
