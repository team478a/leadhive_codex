# フォーム候補の集計

## 目的と操作

企業一覧でプロジェクトを選ぶと「フォーム候補の集計」が表示されます。保存済みの解析から、未解析、営業禁止、連絡禁止、CAPTCHA、確認画面、旧解析、変更検出、解析エラー、フォーム未発見、項目の要確認を分類します。分類ボタンまたは表示対象で絞り、25社ずつ確認できます。「企業詳細を確認」から既存の詳細画面を開きます。

集計はプロジェクト全体が対象です。企業一覧のキーワード・ランク・地域などの絞り込みとは独立しています。企業に複数プロフィールがある場合は主プロフィールを優先し、更新日時・ID順で1件を選ぶため、同じ企業を重複計上しません。

## 候補数と送信許可の違い

「解析条件の候補」は構造上の参考件数です。現行解析バージョン、READY、営業可否ALLOWED、通常配送対応、メッセージ項目、必須項目の対応、確認画面なし、CAPTCHAなし、フォームURL・POST先・fingerprintの保存を確認します。既存の連絡禁止企業は別分類になります。

Suppression、送信結果不明、過去の送信・予約、文面、送信者、Human承認などを含む最終送信許可の件数ではありません。例えば保存済み解析が候補条件を満たしていても、Suppression登録企業は候補数に含まれ、表示した企業の「連絡制御」には禁止理由が表示されます。既存の連絡可否サービスをそのまま利用します。「制限未検出」も承認・実行許可を意味しません。

分類は連絡禁止、営業禁止、未解析、エラー、変更検出、フォーム未発見、CAPTCHA、項目確認、確認画面、旧解析、保存情報不足、候補の順です。複数理由がある企業は先の分類に1回だけ計上します。現行解析は1.2です。旧解析結果の更新は既存のフォーム解析操作で行います。この画面を開いただけでは再解析しません。

## APIとアクセス制御

- `GET /api/projects/{project_id}/form-readiness`
- Humanログイン必須。プロジェクト所有者・メンバーのみ参照可能。Viewerは参照可能。Agent credentialおよびHuman Cookieとの混在は既存認証境界で拒否。
- `category`は固定分類、`limit`は1〜50（既定25）、`offset`は0以上。
- `counts`と`company_total`は全体、`total`と`items`は分類後、`analysis_version`は現行解析、`scope=stored_analysis_not_send_authorization`。
- 集計はSQLで実行し、既存連絡制御の評価は表示ページの企業に限定。会社名・IDで安定した順序。
- DB更新、企業サイトへの通信、解析ジョブ、承認、送信予約、送信は発生しません。Model・Migrationの変更なし。

フロントでは分類切替、ページ送り、禁止理由表示、送信許可と区別した説明、API書き込みなし、デスクトップ・モバイル幅をE2Eで確認します。既存フォーム解析画面も回帰対象です。
