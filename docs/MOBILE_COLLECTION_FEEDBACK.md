# スマートフォンでの収集操作通知

基準: main `302d8db921b41dcba7b2197f88a292b36c94c605`（PR #91）。

収集画面が長いため、フォーム上部にある操作結果を確認するにはスクロールで戻る必要があった。
画面幅640px未満では、収集画面の操作通知を画面下に固定して表示する。
それ以上の画面では従来と同じフォーム内に表示する。

- 収集・Web解析・AI判定のリクエスト中は受付中の表示を出す。
- 成功・エラー通知は自動消去せず、「通知を閉じる」で閉じる。
- バックグラウンド処理への登録通知には「進捗を見る」を表示する。
  押すと通知を閉じ、バックグラウンド処理欄へスクロール・フォーカスする。
- 通知には高さ上限と内部スクロールを設け、端末下部のsafe areaを考慮する。
- バックグラウンド処理への登録は収集完了ではない。実際の状態は既存の処理表示で確認する。

収集API、ワーカー、収集条件、承認・送信条件、DBには変更なし。
PR #92（複数都道府県）・#93（媒体除外）とは独立したUI変更。

## 検証

既存のUI専用Playwright環境でAPIをモックし、Desktop / iPhone 13相当を検証する。
新規ケースは受付中の表示、二重操作防止、受付完了通知、進捗への移動、APIエラー、通知の閉じる操作を確認する。
モバイルは通知全体がviewport内にあり、上へスクロールせず読めることを検証する。
既存の担当者ガイド・収集/営業画面分離テストも実行する。
実サイトアクセス、検索API、AI、送信、本番データ操作は行わない。

実行結果: `npm run typecheck`、`npm run lint`、`npm run build` 成功。
`npx playwright test --config operator-guide.config.ts` は28件成功（Desktop 14 / Mobile 14）。
`git diff --check` 成功。buildの既存500KB超のbundle警告は残る。
DB・Backendコード変更がないため、新しいMigrationやBackendテストの追加は不要。
GitHub CIの結果はPR上で確認する。
