# メール配信失敗通知 実装記録

## 目的

承認済みの営業メールがSMTP接続や配信処理で失敗した場合、送信を承認した利用者がダッシュボードで気付き、企業詳細から内容を確認して再送できるようにする。

## 動作

- ワーカーがメール送信を失敗として確定したとき、承認者へアプリ内通知を作成する
- ワーカー停止により送信中断を検出した場合も同じ通知を作成する
- 通知には企業名、宛先、公開可能な失敗理由を表示する
- 同じ送信試行では重複しない。再送後に再び失敗した場合は新しい通知を作成する
- 通知を開いた利用者は企業詳細で送信内容を確認し、明示承認のうえで再送する

通知はSMTPの受信側で発生する迷惑メール判定やバウンスを検知するものではない。SMTPへ渡すまでの送信処理失敗を対象とする。

## API

既存の通知APIで取得・既読化できる。

- `GET /api/notifications`
- `POST /api/notifications/{notification_id}/read`
- `POST /api/notifications/read-all`

通知の種別は `email_delivery_failed` で、`email_delivery_id` から対象の送信予約を識別できる。

## 検証

- SMTP送信失敗時に承認者だけへ通知が作成されること
- 通知が送信予約と企業へ紐付くこと
- 既存の通知一覧・既読処理、Migrationのupgrade / downgrade、全自動テスト、ビルド
