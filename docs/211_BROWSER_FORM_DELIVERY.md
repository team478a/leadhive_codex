# 211 ブラウザによるフォーム送信

作成: 2026-10-17。状態: **安全基盤を実装。実サイトの解析・入力・送信は未許可**。

## 目的と境界

ブラウザーによるフォーム解析・入力の将来計画。実サイトへのアクセスとフォーム送信は、別途明示的な承認があるまで行わない。この変更はブラウザーの安全基盤と合成フォーム専用のOperationJob経路を用意するだけで、企業URLや外部フォームURLを受け付けない。送信・承認・送信上限・連絡禁止の既存判定は変更しない。

## 実サイトを開く前に必要なもの

### 通信先を制限する

- browser workerコンテナ内のloopbackだけで待ち受けるHTTPS CONNECTプロキシを使用する。Chromiumには `--proxy-server` を必ず指定し、loopbackを含むプロキシ迂回を無効にする。WebRTCとQUICも無効にする。
- プロキシはHTTPSの443番だけを扱い、CONNECTごとに許可ドメインを照合する。許可リストは対象サイトのホスト（`www` のみ同一扱い）と、承認計画に明記された外部フォームの完全一致ドメインだけとする。任意のURL・ワイルドカードは受け付けない。
- 接続ごとに既存の `pinned_dns` でDNSを解決し、既存の `public_addresses` で全回答を検証する。非公開・特殊用途IPが1つでも混ざる回答は拒否する。接続先には検証済みの数値IPを渡して固定し、ホスト名の再解決や別IPへのフォールバックを許さない。
- Playwrightのリクエスト遮断も残し、プロキシとブラウザー側の二重防御にする。フォーム送信、ファイル選択、ダウンロード、新しいウィンドウも許可しない。

### ページを開く前に確認する

- 最初のページ遷移より前に、同じプロキシ経由で `robots.txt` を取得する。既存の `SafeFetcher` と同じ `urllib.robotparser` 判定を共通関数で使用する。
- 取得失敗、サイズ超過、未対応HTTP応答、リダイレクトは許可の証拠とみなさず停止する。404は既存の `SafeFetcher` と同様に許可、401/403およびDisallowは拒否する。
- メインフレームの各遷移で、パスワード欄、ページ本文・タイトルのログイン／サインイン表示、ログイン系パスを検査する。該当時は直ちに処理を停止する。

## OperationJobと実行範囲

- `browser_form_analysis` は既存OperationJobのactive-project/type一意制約、lease、cancel、stale recoveryを使う。通常のapplication workerはこの種類をclaimしない。
- 専用API `POST /api/projects/{project_id}/browser-form-analysis` は、パッケージ済みfixture名とサイズ制限付き入力値だけを受け付ける。未知のfixture名や追加フィールド（URLなど）は拒否する。browser workerも実行直前にpayloadを再検証する。
- browser workerは合成HTMLだけを開き、送信処理は実行しない。`browser_form_delivery_enabled` は既定OFFのままで、送信機能・本番workerのデプロイ・Renderサービス追加はこの作業に含めない。

## テストと確認

browser workerのテストは合成フォームとlocalhostのテストサーバーのみを使う。許可外ホスト、IPリテラル、内部IP、DNS再束縛、robots拒否、ログイン遷移、ダウンロード、新しいウィンドウ、ファイル選択、送信試行、OperationJobの割当・重複防止・cancel・復旧を確認する。実サイトへのアクセスやフォーム送信を含むテストは追加しない。

## 次の工程（別途承認が必要）

1. ブラウザー描画後のフォーム解析を保存する。実サイトの読み込みは明示承認後に限る。
2. 入力計画と人の確認・承認を既存の承認モデルへ接続する。
3. 承認済みブラウザー送信は、既存の予約・二重送信防止・サイト間隔・時間帯・上限・連絡禁止を再利用して別変更で設計する。
4. 実サイトへの段階的アクセス・送信は、それぞれ段階ごとに明示承認を得る。

CAPTCHAの自動化、bot検知回避、CAPTCHA解読サービス、未承認のフォーム送信は行わない。
