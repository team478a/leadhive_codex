# 入力専用の準備・結果確認改善

## ゴールと基準

基準main: `6971f70ae7b32045e8eb38c5ea829a52d781b779`。

## 修正

- フォーム解析結果が非同期で到着しても、主フォームの入力欄を自動表示する。
  URLが選択済みのように見えて入力欄が空になり、同じURLの再選択が必要だった問題を解消。
- 依頼発行後は、同じ画面で依頼を重ねて作成しない。宛先・入力欄も固定する。
  作り直す場合は既存の取消APIを使用してから作成する。
- 成功／技術停止／人の確認／禁止を日本語で表示する。
  最新の未送信PC報告から、入力確認項目数と停止理由を表示する。
  既存Activityを利用し、再表示時も同じ企業の報告だけを読む。
- 不明な理由コードを成功と推測しない。詳細表示で理由コードと日時を確認できる。
- 常時表示していた「有効化が必要」という一般説明を、実際の無効状態と誤認しない表現へ変更。
- 操作は「内容確認 → PCで入力 → 結果確認」。詳しいPC手順は展開表示する。

## 維持する境界

API・DB・migration・ランナー・通信制御・Human Approval・送信経路は変更していない。
PC報告は `PC_REPORTED_UNVERIFIED` のまま。入力成功は営業許可や送信承認ではない。
企業・Project・依頼ID・hash・未送信フラグの既存取込検証を維持する。
入力値・tokenを結果表示・新しい履歴へ保存しない。
営業NGとviewerの依頼作成禁止、15分・単一用途の既存チケット制約を維持する。

## まだ必要なPC操作

クラウド画面からローカルPCを直接起動する機能は追加していない。
PC用JSONの保存、PCランナーでのファイル選択、結果JSONの取込は残る。
スマートフォンからは準備・結果閲覧ができるが、入力実行はPCが必要。
期限切れの未報告依頼を作り直す場合も、取消してから新しい依頼を作る。
既存の汎用活動履歴のJSON表示は維持し、本パネルで読みやすい結果を追加する。
