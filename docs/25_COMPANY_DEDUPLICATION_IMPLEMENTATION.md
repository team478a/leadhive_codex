# 重複候補・企業統合 実装記録

## 目的

収集元や検索条件が異なるため登録時に判定できなかった重複企業を検出し、営業履歴を失わず1社へ統合する。

## 重複候補

同一プロジェクト内で次のいずれかが一致する組み合わせを最大100組返す。

- 大文字・小文字を区別しないメールアドレス
- 空でない電話番号
- 大文字・小文字を区別しない会社名と住所の両方

空欄同士は一致として扱わない。候補画面には一致した根拠を表示し、自動統合は行わない。

## 統合

ユーザーが残す企業を明示的に選び、確認ダイアログを承認した場合だけ統合する。APIでも一致根拠を
再検証し、候補ではない2社は409で拒否する。

統合時の処理:

- 残す企業の値を優先
- 残す企業が空欄の基本情報・連絡先・Web解析・AI要約を統合元から補完
- メモを両方保持
- 次回対応日時が未設定なら統合元から補完
- 活動履歴を残す企業へ移動
- 他企業から統合元への重複参照を残す企業へ付け替え
- 統合元企業を削除
- 統合操作を活動履歴へ記録

営業状況や既存スコアなど、残す企業に設定済みの判断情報は上書きしない。

## API

| Method | Path | 内容 |
| --- | --- | --- |
| GET | `/api/projects/{project_id}/duplicate-candidates` | 候補と一致理由 |
| POST | `/api/projects/{project_id}/companies/merge` | `target_id`へ`source_id`を統合 |

双方が同一の所有プロジェクトに存在することを検証する。

## 検証

- 電話一致による候補検出
- 根拠のない組み合わせの拒否
- 空欄情報とメモの補完
- 活動履歴と重複参照の移動
- 統合元削除と監査履歴
- バックエンド全テスト、Ruff、typecheck、lint、build、デスクトップ・モバイルE2E
