# 記事企業抽出 Pilot 手順書

**この手順書は実行承認ではありません。** 田中さんの明示承認を得るまで、記事GET、抽出operation作成、候補取込、Production DBの閲覧・集計を実行しません。

## 実行前ゲート

- 田中さんから、対象範囲・実施時期・最大10記事のGETを含む明示承認を得る。
- 読み取り専用在庫集計で対象が既存保存済み `ARTICLE` hitであることを確認する。新規検索や記事URLの収集はしない。
- 大阪府・兵庫県の「SNS運用代行 会社」に関する既存hitから最大10記事を選ぶ。対象URL・理由・重複・保持期限を人が確認する。
- 営業用ではない独立した検証Projectを準備し、候補・Companyが営業Projectへ流れないことを確認する。
- `extract_articles` の `article_limit` を10以下に固定し、利用するextractor version、実行者、時刻、出典保存条件を記録する。
- Human承認、Web解析、AI、Serper等の検索API、メール／フォーム送信は無効のままにする。

## 実行と確認

- 保存済みhitだけを入力し、最大10件の安全な記事取得を行う。robots拒否、redirect、timeout、非HTML、サイズ上限の扱いを確認する。
- 取得状態・抽出pattern・`LINKED` / `NAME_ONLY` / `REJECTED` 数・新規候補・重複／除外・処理時間を記録する。
- 新規候補を全件、人が「掲載企業と一致／記事運営会社／別会社／広告／判断不可」で確認する。未確認を正解扱いしない。
- 誤登録率はHuman確認済み候補のみを分母にして計算し、対象件数と未確認件数を併記する。
- 記録先は `docs/208_ARTICLE_EXTRACTION_PILOT.md`。結果の後で停止し、名称のみ行のsite lookupやAI抽出には進まない。

## 即時停止条件

記事運営会社・広告・ナビが候補として取り込まれる、中継リンク追跡・別サイトredirect・robots拒否URLへの取得、既存重複／suppression／除外の迂回、Project越境、検索API・AI・送信の発生、件数目標や収集停止判定の変化があれば直ちに停止して記録する。原因確認と再実行には別途承認が必要。

## 安全境界

- 対象は保存済み検索hitのみ。Serper再検索、企業サイトGET、Web解析、AI判定、送信はしない。
- GET上限は10記事（robots確認を除く）。実装側の安全なfetch制約を弱めない。
- ProductionのDB schema/dataを変更しない。候補登録は隔離された検証Projectのみ。
- Pilot前後の在庫差分・候補数・Human判定を分けて記録し、抽出件数を精度の証明として扱わない。
