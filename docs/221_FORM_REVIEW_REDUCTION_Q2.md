# フォーム確認削減 Q2：同意欄の運営ルール

## 目的

フォーム確認キューにある同意チェック欄のうち、安全条件をすべて満たすものだけを、プロジェクト所有者が承認した版付きルールで自動判断する。設定はプロジェクト単位で、既定は無効である。対象サイトへのアクセス、AI判定、承認依頼の作成、送信は行わない。

## CONSENT_POLICY_V1 の全条件

個人情報への同意を自動でチェックするのは、次の条件をすべて満たす欄だけである。

1. `mapped_key == 'privacy_consent'`
2. `field_type == 'checkbox'` で、選択肢がちょうど1つあり、その送信値が空でない
3. 項目名または選択肢の文言に「個人情報」「プライバシー」「privacy」のいずれかを含む
4. 文言に「メルマガ」「メールマガジン」「newsletter」「配信」「お知らせ」「キャンペーン」「広告」を含まない
5. 文言に「同意しない」「希望しない」「受け取らない」「拒否」「disagree」「decline」「unsubscribe」「not agree」を含まない
6. 項目名に「必須性未確認」を含まない

`newsletter_consent` は任意欄だけを未選択として自動判断する。必須欄は自動判断しない。

## 人の確認に残るもの

- 個人情報とメルマガ・広告・配信希望が混在する欄
- 必須のメルマガ同意欄
- 否定表現を含む欄
- 選択肢が複数、送信値が空、または必須性未確認の欄
- 連絡方法、本文入力先など、同意欄以外の未解決項目
- 以前は一致していても、再解析後の文言や選択肢が現在の条件を満たさなくなった `POLICY` 欄

既存の `MANUAL` 決定は上書きしない。自動判断した欄は `decision_source='POLICY'`、`confidence=1.0` とし、欄ごとに `policy_applied` の解析ログを保存する。

## 操作

フォーム確認キューの「同意欄の自動判断」で条件全文を確認する。プロジェクト所有者だけが、確認チェックを付けて有効化できる。有効化時は現在の確認キューを100フォームずつ処理し、件数と進捗を表示する。

無効化しても既存の `POLICY` 決定は保持する。「このルールで決めた欄を未決定に戻す」では、`POLICY` の欄だけを `RULE`・空値へ戻し、`MANUAL` の欄には触れない。有効化、無効化、取り消し要求は操作者、日時、ルール版を監査記録へ残す。

解析・再解析後も、設定が有効なプロジェクトだけに同じルールを適用する。適用または取り消し後は共通関数でフォーム状態を再計算し、実行待ち・実行中の同種ジョブがない場合だけ送信可否の再集計を登録する。

## 安全境界

- 送信可否の判定、Human承認、送信直前確認は緩めない。
- 自動判断は保存済みフォーム項目だけを対象とし、外部サイトへ接続しない。
- 送信ジョブ、送信予約、承認依頼は作成しない。
- ルール条件を変更するときは版を上げ、既存の決定を黙って転用しない。

## API

- `GET /api/projects/{project_id}/consent-policy`
- `POST /api/projects/{project_id}/consent-policy/enable`
- `POST /api/projects/{project_id}/consent-policy/disable`
- `POST /api/projects/{project_id}/consent-policy/reset`

参照はプロジェクト閲覧者が行える。変更操作はプロジェクト所有者だけが行える。
