# 運用優先のフォーム解析・営業NGリスト

基準: main `4e869ade2b8997649d95b52f620cd25438249b81`。解析版: 2.0。

## 運用方針

収集した企業サイトから問い合わせ窓口を探し、入力項目を解析する。
営業NGを検出した対象は送らず、営業NGリストへ分類する。
技術的に止まった対象は、取得・項目・経路の理由を見て修正する。
Human承認、Suppression、UNKNOWN再送防止、CAPTCHA制御は維持する。

## 今回まとめた変更

- 公式サイト内の実リンクから発見した外部問い合わせページも解析する。
  最大3ページ。外部サイト内の再帰探索・推測URL探索・検索API追加はしない。
- 同一のSafeFetcherで、既存の合計32リクエスト・60秒上限、robots、URL検証、
  同一ホストへの転送制限を維持。外部候補ごとに取得先を固定する。
- 取得したフォームを既存FormProfile・FormProfileFieldへ保存し、既存画面で
  入力項目、マッピング、技術対応、CAPTCHA、取得失敗理由を確認できる。
- 外部サービスのフォーム存在は企業同一性や営業許可の証明ではない。
  営業NG以外はUNCERTAINとし、技術対応とは独立して扱う。
- フォーム未検出ページでも営業NGを検出する。長文ページの末尾も対象。
  AI向け本文の切り詰めを営業NG検出へ適用しない。
- 検出企業に既存do_not_contactを設定し、理由を「営業NG：」として保存。
  既存の理由も保持。検出URLと該当文をFormAnalysisLogへ記録。
  フォームだけでなく既存メール等の連絡ガードも停止する。
- 企業一覧 → フォーム候補の集計 → **営業NGリスト**で対象を確認できる。
  企業を削除・別Projectへ移動しない。再解析でNG表記が消えても自動解除しない。
- 未取得の候補をフォームなしと表示しない。現行の解析結果と取得上限対象外を区別。

## 検証と提供範囲

専用PostgreSQL `_test` DBでフォーム解析・集計・営業禁止ルール・連絡制御・
承認付きフォームの回帰テストを実行する。画面はdesktop/mobileの既存Playwrightで確認。
既存のlocalhostブラウザPoCも再実行し、入力・確認画面・入力エラー・NG時の停止を確認する。

実行結果: Backend回帰127件成功、画面E2E desktop/mobile計4件成功、
localhostブラウザPoC計44件成功。Ruff・format・mypy・Frontend typecheck・lint・build成功。
Backendと画面テストは同じ専用DBを使うため順次実行する。

実企業へのGET、ブラウザ入力、POST、営業送信、Human承認は今回実行しない。
クラウドの送信OFFや設定は変更しない。DB Migration・外部依存追加はない。

## 残る運用上の範囲

本PRは外部フォームの解析とNGへの振り分けを既存の入力候補表示へ接続する。
汎用ブラウザ入力ランナーの本番接続は未実装。JavaScriptや複雑な構造の入力可否は
実サイトで検証済みとはしない。HTTP/既存対応経路とCodex支援の承認境界を維持する。
未取得・未対応は理由を残し、使用時に発生した問題を対象別に直す。

PR統合後は新しい解析を行った対象から本仕様を適用する。過去企業の一括再解析や
NGの自動一括付与は行わない。実運用の取得成功率・入力成功率はまだ未測定。
