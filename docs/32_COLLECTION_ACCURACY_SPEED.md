# 検索収集の精度・速度改善 実装記録

## 目的

企業公式サイトではない検索結果を早い段階で除外し、複数キーワードの待ち時間を短縮する。

## 公式サイト外の早期除外

検索、URL、CSVから得た候補をDBへ保存する前にドメインを正規化し、既存の公式サイト判定でSNS、動画、求人、地図、企業ポータル、百科事典などを除外する。

これにより次を削減する。

- 営業リストへのノイズ混入
- 不要なWeb解析リクエスト
- 不要なAI判定とAPI費用

除外数は`collection_jobs.excluded_count`へ重複・エラーと分けて記録し、収集履歴と定期検索成果に表示する。

## 並列検索

通常のバックグラウンド検索収集では、複数キーワードの外部検索を最大4件並列で実行する。取得結果のDB保存、重複判定、抑止リスト判定、進捗更新はメインスレッドで順番に処理する。

企業数上限が設定された定期収集は上限超過を防ぐため、従来どおりキーワード単位の逐次処理を維持する。キャンセル判定と失敗の個別記録も維持する。

## 計測

収集ジョブの開始から保存完了までをミリ秒で`processing_ms`へ記録する。既存ジョブはMigrationで0に補完する。

## 検証

- SNSドメインを保存前に除外し、発見・保存・重複・公式外・エラーを別々に集計
- 2検索が同時に実行開始されることを同期バリアで確認
- 検索の部分失敗、進捗、再実行など既存動作を維持
- Migrationのdowngrade / upgradeとAlembic差分検査
- 型検査、Lint、本番ビルド、ブラウザE2E
