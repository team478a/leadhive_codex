# バックグラウンド処理監視 実装記録

## 目的

バックグラウンド処理の失敗をユーザーが見落とさず、原因と進捗をダッシュボードで確認できるようにする。

## 実装

- 失敗ジョブの確認日時 `acknowledged_at`
- 所有ユーザーごとの未確認失敗件数
- 状態別ジョブ件数と直近10件の処理履歴
- サイドバーのダッシュボード項目に未確認件数を表示
- ダッシュボードで処理種別、状態、進捗、試行回数、公開可能な失敗理由を表示
- 失敗通知の確認済み操作
- 失敗ジョブを再実行した際に元通知を自動で確認済み化

ジョブと通知を別テーブルへ複製せず、失敗した `operation_jobs` 自体を永続通知として扱う。
処理状態と通知内容がずれることを防ぎ、プロジェクト削除時には関連通知も同時に削除される。

## API

`GET /api/dashboard`へ次の項目を追加した。

- `operation_statuses`: 状態別の件数
- `unread_operation_failures`: 未確認失敗件数
- `recent_operations`: 直近10件のジョブ

`POST /api/operations/{job_id}/acknowledge`は、所有者の失敗ジョブだけを確認済みにする。
他ユーザーのジョブは404、失敗以外のジョブは409を返す。

## 検証

- 失敗ジョブの集計と未確認件数
- 確認済み更新と所有権チェック
- 完了ジョブの確認済み操作拒否
- Alembic downgrade / upgrade / model差分確認
- バックエンド全テスト、Ruff、フロントエンド typecheck / lint / build
- デスクトップ・モバイルE2E

メールや外部チャットへの通知は送信先設定と配信基盤が必要なため、この段階ではアプリ内通知に限定した。
