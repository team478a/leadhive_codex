# 一括フォームDM 実装記録

## 目的

選択した営業候補へ同じフォーム文面を適用し、送信可能な通常フォームを承認後に順番に処理する。フォームごとの必須項目やCAPTCHAを無視した送信は行わず、対応できない企業をCodex支援の作業対象として残す。

## 操作

企業一覧で対象企業を選択し、フォーム文面テンプレートから一括フォームDMを作成する。作成時点では外部サイトへ送信しない。連絡禁止、フォームURL未登録、既にフォーム送信済みの企業は対象外として理由を記録する。

利用者が対象件数・文面・除外結果を確認して承認すると、最大20社ずつ順番に送信する。各フォームを再取得して、本文だけで必須項目を満たせる通常POSTフォームに限り送信する。

## 結果

| 状態 | 内容 |
| --- | --- |
| 送信待ち | 次回の実行対象 |
| 送信済み | 通常フォーム送信を完了し、活動履歴と営業状況へ反映 |
| Codex支援 | CAPTCHA、選択式入力、追加の必須項目などにより個別確認が必要 |
| 対象外 | 連絡禁止、フォームURLなし、送信済み |
| 失敗 | 送信処理中の予期しない失敗 |

Codex支援対象は外部サイトへ送信されない。企業詳細の既存Codex支援フォーム送信で、画面を確認しながら個別に対応する。

## 安全条件

- 作成時に外部送信しない
- 実行時に明示承認を必須にする
- 連絡禁止企業を送信しない
- 同一企業への送信済みフォームDMを重複させない
- CAPTCHA、選択式入力、外部サイト送信、必須項目不足は自動送信しない
- 送信結果を企業・文面・活動履歴へ記録する

## API

- `GET /api/projects/{project_id}/form-delivery-batches`
- `POST /api/projects/{project_id}/form-delivery-batches`
- `POST /api/form-delivery-batches/{batch_id}/execute`
- `POST /api/form-delivery-batches/{batch_id}/cancel`

## 検証

送信前承認、連絡禁止除外、通常フォーム2件の順次送信、活動履歴・送信記録、Migration整合を実PostgreSQLで確認する。
