# 送信成果の直接帰属 実装記録

## 目的

送信方法・文面別の成果を、企業の現在の営業状況ではなく、実際に受け取った返信とその後の対応へ直接結び付けて比較できるようにする。

## 帰属の流れ

1. 受信メールが返信として企業へ照合されると、受信日時以前の最も新しい送信完了済みの文面へ紐付ける。
2. この紐付け時に「返信」を成果として記録する。
3. 返信対応キューから商談化または成約を記録すると、同じ承認済み送信へ「商談」または「成約」を記録する。

不達通知・配信停止依頼は成果として記録しない。承認済み送信が見つからない返信は、通常どおり企業の営業状況を更新するが、送信成果分析には含めない。

## 分析

`GET /api/outreach-effectiveness-analytics?days=30` は、指定期間に送信完了した文面を分母にして、紐付いた成果を送信方法と件名ごとに集計する。同じ送信に複数の返信があっても、返信・商談・成約は各送信につき一件として数える。

過去に取り込んだ返信は自動で遡及帰属しない。既存の返信対応は継続して記録できるが、以後の受信取込、または未照合メールの手動紐付けから成果記録を作成する。
