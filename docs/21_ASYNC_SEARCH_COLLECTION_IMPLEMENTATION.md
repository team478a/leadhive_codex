# 検索収集の非同期化 実装記録

## 目的

Serper・Google Placesによる検索収集をHTTPリクエスト中に完了させず、件数や外部APIの応答時間に
かかわらず画面操作を継続できるようにする。

## 画面動作

検索フォームから実行すると `collect_search` のバックグラウンドジョブを登録し、すぐ画面へ戻る。
バックグラウンド処理欄では待機、実行中、完了、失敗、キャンセルの状態とキーワード単位の進捗を
確認できる。待機中・実行中はキャンセルでき、失敗・キャンセル後は同じ条件で再実行できる。

URL直接入力とCSV取込は外部API待ちを伴わず、入力結果をその場で確認する用途のため同期処理を維持した。

## ワーカー動作

1. 入力されたキーワード数を総件数として記録
2. キーワードごとに既存の `collection_jobs` を作成
3. SerperまたはPlacesから候補を取得
4. URL正規化と重複判定を行って企業を保存
5. 成功・失敗件数とリースを更新
6. 一部でも失敗した場合は処理ジョブを失敗として通知

外部サービスの公開可能なエラーは個別収集ジョブに保存する。バックグラウンド処理には内部例外を
含めず「一部の処理に失敗しました」と表示し、詳細は収集ジョブ一覧で確認する。

## 互換性

既存の `POST /api/projects/{id}/collection-jobs/search` はAPI互換性のため維持する。
画面は `POST /api/projects/{id}/operations` を使用する。

## 検証

- 複数キーワードの成功・外部API失敗の混在
- 企業・収集ジョブ・進捗件数の保存
- 失敗通知への反映
- 画面からの登録、待機表示、キャンセル
- バックエンド全テスト、Ruff、typecheck、lint、build、デスクトップ・モバイルE2E
