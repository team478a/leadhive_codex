# 公式サイト由来の外部問い合わせ候補

## 基準と問題

基準: main `14f55fc8c2c21c5e5813b3331bb047aacd2e709b`。
igac.net の公開サービスページには「お問い合わせ」から外部フォームへ進む導線がある。
既存 `navigation_links` は同じサイト以外を除外するため、この導線は解析対象にも確認候補にも残らなかった。
2026-10-10 のブラウザ閲覧では外部ページの会社名・メール・問い合わせ本文欄を確認した。
営業利用の許可や実送信は確認していない。

## 修正

- 完全一致の問い合わせラベルから HTTPS の外部候補を抽出する。
- 既存 FormAnalysisLog に URL、発見元 URL、ラベル、OFFICIAL_SITE_LINK、EXTERNAL_CONTACT_UNVERIFIED を記録。
- 解析1回あたり最大8候補。同じURLは重複記録しない。クエリ識別子は保持する。
- 企業詳細の「フォーム事前解析」に候補と出典を表示。クリックして確認できる。
- 最新の解析開始以後の候補を表示し、過去解析の候補を現在の発見と混同しない。
- フォーム存在・窓口用途・営業可否は未確認と明示。

## 安全境界

外部候補は crawl queue に追加しない。外部GET、自動フォーム解析、POST、承認、送信には接続しない。
企業の contact_url、ContactDestination、FormProfile の READY、営業許可、送信方式を自動変更しない。
既存の SafeFetcher、SSRF、robots、別ドメインへの転送拒否、取得予算は維持する。
候補記録では不正URL、認証情報入りURL、非HTTPS、非標準ポート、ローカルホスト・非公開IP等を除外する。
候補のホストは取得時のDNS安全検証を受けていないため、将来の自動取得前には別途 SafeFetcher の検証が必要。

## 変更範囲

contact_discovery.py、form_intelligence/analyzer.py、CompanyFormIntelligencePanel.tsx。
既存のプロジェクト権限と解析ログ取得APIを再利用。Migration・新API・依存追加なし。

## 検証

単体テスト: 外部候補の保存形式・クエリ保持・重複除去・危険URL・無関係リンク・上限・既存同一サイト探索。
DB統合テスト: 外部URLを取得しない、既存フォーム状態は未確認、企業contact_urlを変更しない、出典ログ1件。
Desktop/Mobile共通E2Eに未確認表示、リンク、出典、承認操作がないことの検証を追加。
実データの自動探索改善は、このPRの統合・反映後に再解析して検証する。本PRは本番有効化しない。

## 残課題

完全一致以外の文言・画像リンク・iframe・JavaScriptリンクは今回の外部候補記録対象外。
外部サービス上のフォーム確認、営業用途確認、技術対応、Human Approvalは独立した次工程。
この修正だけでDM READYや送信可能件数が増えたとは報告しない。
