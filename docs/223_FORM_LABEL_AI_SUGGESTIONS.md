# 未解決フォーム項目のAI候補

## 目的

Q3の項目名ルールで人が対応先を決める際に、保存済みの未解決項目から安全条件を満たす候補だけを提示する。AIの回答は送信値、承認、送信許可として扱わず、人が既存の項目名ルールを保存するまではフォーム項目へ反映しない。

## 操作

1. 「送信の準備・実行」からフォーム確認キューを開く。
2. 「項目名ごとに決める」タブを開く。
3. 未解決の項目名にある「AI候補を表示」を押す。
4. 表示された候補、確信度、確認した例数を確認する。
5. 正しい場合だけ「このルールを保存して…フォームに反映」を押す。誤り・不要な候補は「AI候補を破棄」を押す。

AI候補の取得にはOpenAI API費用が発生する。同じ未解決項目名・型に未処理の候補または「候補なし」の結果が保存済みなら、再度APIを呼ばず保存済み結果を返す。

## AIへ渡す情報

- プロジェクトの営業目的（最大2,000文字）
- 正規化前の項目ラベル、`name`、型、必須性、選択肢
- 同じ正規化項目名・型から最大20例

ページ本文、会社情報、フォームURL、周辺文言、文面、送信者情報は渡さない。対象サイトへの新しいアクセスも行わない。

## 安全条件

候補を表示するには、最大20例の全件で次を満たす必要がある。

- AIが全例に回答している
- 全例の対応先が同じ
- 全例の確信度が90%以上
- `unknown`、`other`、個人情報同意、メルマガ同意ではない
- 型と対応先が一致する
  - `textarea` は本文だけ
  - `email` はメールアドレスだけ
  - `tel` は電話番号系だけ
  - `url` はWebサイトだけ
  - `select`／`radio` は都道府県、市区町村、部署、役職、問い合わせ種別、連絡方法だけ
  - `checkbox` と仕組み用の型は候補対象外

1件でも条件を満たさない場合は対応先を保存せず、「AI候補なし」と理由だけを保存する。AIが返した選択値は採用しない。

## 保存と監査

`form_label_ai_suggestions` に、プロジェクト、正規化項目名、型、候補キー、最低確信度、確認例数、provider、model、usage、作成者、状態を保存する。状態は次のとおり。

- `ACTIVE`: 人の確認待ち
- `ACCEPTED`: 人が同じ対応先の項目名ルールを保存した
- `DISMISSED`: 人が破棄した
- `UNAVAILABLE`: 安全条件を満たす候補がなかった

`ACCEPTED` への変更時に、作成された `form_label_rules.id` を保存する。候補と項目名・型・対応先が一致しない場合は候補由来として保存できない。

## 非実行境界

- 候補作成だけでは `FormProfileField` を変更しない。
- 候補作成だけでは `OperationJob`、承認依頼、配送予約、送信結果を作成しない。
- ルール保存後の反映はQ3の既存バックグラウンド処理を使う。
- 対象サイトへのアクセス、承認、承認依頼、送信は行わない。

## API

- `GET /api/projects/{project_id}/form-label-rules`
  - ルールに加えてAI候補とAI設定可否を返す。
- `POST /api/projects/{project_id}/form-label-rules/ai-suggestions`
  - 1つの正規化項目名・型について候補を作成、または保存済み結果を返す。
- `POST /api/projects/{project_id}/form-label-rules/ai-suggestions/{suggestion_id}/dismiss`
  - 候補を破棄する。
- `POST /api/projects/{project_id}/form-label-rules`
  - 任意の `ai_suggestion_id` が完全一致する場合、ルール保存と同時に候補を採用済みにする。

すべて既存のプロジェクト権限を使い、候補作成・破棄・ルール保存は編集権限を必要とする。
