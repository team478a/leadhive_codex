# フォームDM自動化

フォーム単位の事前確認・一括承認・自動送信を段階的に整備する。承認経路の既存安全判定を再利用し、同意・営業可否・CAPTCHA・二重送信・UNKNOWN・送信枠の防御を弱めない。

## PR計画

1. **PR-0 送信不可理由の内訳**：読み取り専用API、理由別件数、20件ページ、CSV、送信準備画面での確認。実サイトアクセス・送信・AI呼び出しなし。
2. **PR-1 フォーム確認キュー**：フォーム構造に結び付いた人の確認を保存。構造変更時は確認を無効化する。
3. **PR-2 承認提案の一括作成と日次承認**：PR-1マージ後に実施。提案作成のみで、送信・予約はしない。
4. PR-0の理由別実数を確認してから、確認画面ありフォーム対応の要否を判断する。CAPTCHAは自動化しない。Contact Form 7・JavaScript送信はPR-0の件数を確認後、別指示書211で扱う。

運用送信の段階変更は別途Human承認が必要。自動マージ・自動デプロイは禁止。

## PR-0のAPI

`GET /api/projects/{project_id}/form-dm-readiness` は保存済みの主フォームプロフィールだけを対象にし、既存の連絡権限・重複・送信準備判定を使って主理由と副理由を返す。`offset` で20件ずつ表示し、`format=csv` で全件を出力する。GETはデータを変更せず、外部通信を行わない。

分類順：`CONTACT_PROHIBITED`、`ALREADY_SENT_OR_UNKNOWN`、`CAPTCHA`、互換性理由、確認画面、同意・選択・マッピング確認、フォームDraft、送信者設定、`READY`。
