# SMTP設定管理とテスト送信 実装記録

## 目的

メール送信に必要なSMTP設定を管理画面から保存し、実際の営業メールを予約する前にテスト送信で接続を確認できるようにする。

## 管理画面

管理者だけにサイドバーの「メール設定」を表示する。以下を保存できる。

- SMTPホストとポート
- ユーザー名とパスワード
- 送信元メールアドレスと送信者名
- STARTTLSの利用
- 接続タイムアウト

初回に作成したユーザーは管理者になる。既存環境ではMigration時点で最初のユーザーを管理者にする。

## 秘密情報の扱い

SMTPパスワードは管理画面へ再表示せず、DBには暗号化して保存する。暗号化キーは`.env`の`SETTINGS_ENCRYPTION_KEY`で管理し、Gitへ含めない。

暗号化キーが未設定または不正な場合は設定を保存できない。SMTP設定を更新しても、パスワード欄を空欄にすれば既存のパスワードを維持する。

## テスト送信

保存済みSMTP設定で、管理者が指定したメールアドレスへテストメールを1通だけ送信できる。操作前に確認ダイアログを表示する。テスト送信は営業活動履歴や営業メールの送信キューへ登録しない。

## API

- `GET /api/admin/smtp-settings`
- `PUT /api/admin/smtp-settings`
- `POST /api/admin/smtp-settings/test`

管理者以外のユーザーには設定の存在を開示しない。

## 検証

- 管理者による設定保存と暗号化保存
- パスワードをAPI・画面へ返さないこと
- パスワード空欄時の既存値維持
- テスト送信の実行経路
- 非管理者のアクセス拒否
- デスクトップ・モバイルでの設定保存
- Migrationのdowngrade / upgrade、全自動テスト、ビルド
