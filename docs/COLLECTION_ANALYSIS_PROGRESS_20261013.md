# 収集済み企業の解析操作表示

## 問題と変更
- 一括解析のボタンはAPIへの登録中だけ状態を表示しており、ジョブが待機中・実行中でも通常表示に戻っていた。
- 現在のプロジェクトのWeb解析・AI判定ジョブを見て、待機/実行の間はボタンを反転（白背景・緑文字・緑枠）、状態を明記し、重複クリックを防ぐ。
- 完了・失敗・キャンセル後は通常のボタン表示と対象有無の判定へ戻る。既存2秒ポーリングで自動反映。
- 更新ボタンのPromiseエラーは画面に出ていなかった。更新専用の受付状態を設け、収集の受付状態とは分ける。処理中は更新中…、成功/失敗を通知し、失敗後も再試行可能。

## 範囲
Frontendのみ。解析内容・バックエンドのジョブ状態・承認条件・送信機能を変更しない。実企業へのアクセス、AI利用、収集・送信を今回のテストでは行わない。

## 検証
PlaywrightモックでWeb解析/AI判定の待機→実行→完了、反転色、重複POST防止、更新エラー→再試行をPCとスマートフォンで確認する。既存の収集受付・通知テストも実行。Frontend typecheck/lint/buildとAPI importを確認。実環境で待機が長く続く原因は、本変更だけでは判定できない。

- `npm run typecheck` / `npm run lint` / `npm run build`: 成功。
- `npx playwright test --config operator-guide.config.ts operator-tests/action-feedback.spec.ts`: 6件成功（PC3件・スマートフォン3件）。
- `python -c "import app.main"`: 成功。
- 本番データ変更・実サイト解析・AI利用・デプロイは行っていない。

## 収集と解析のページ分離

ユーザーの運用に合わせ、収集だけ済ませて後からまとめて解析できる導線に変更。

1. 収集ターゲット設定
2. 企業収集：検索/URL/CSV、収集履歴と収集の進捗。解析操作は表示しない。
3. リスト解析：保存済みプロジェクトを選択し、Web解析とAI判定を明示的に実行。検索条件・収集ボタンは表示しない。解析履歴を上部に表示。
4. 結果確認：既存OK/NG/URL修正。

解析ページは収集用の履歴・スケジュール・集計APIを呼び出さず、企業一覧と解析ジョブを取得。既存のジョブ/APIと更新・色反転を再利用する。ページ遷移で解析/収集を自動開始しない。対象プロジェクトを引き継ぎ、企業一覧は20社単位で表示。既存の一括解析上限100社は画面と担当者ガイドに明記。残件の自動追加や新しいAI呼び出しは実装していない。

PR #99に追加コミットとしてまとめ、共有履歴は書き換えない。型チェック/Lint/ビルド成功。画面テストは全operator suiteで再検証。

ページ分離後の最終検証：`npx playwright test --config operator-guide.config.ts` は38件成功（PC19件・スマートフォン19件）。収集と解析の操作分離、プロジェクト引継ぎ、遷移時POSTなし、状態反転・復帰、結果確認、既存営業導線を検証。

## CIの旧画面期待値の修正

`c5fad9c19ec8fa3a78b587ae198e6bad158551be` のpush/PR CIは、どちらも `workflow.spec.ts:104` で失敗（PC・スマートフォン各1件、111件成功）。企業カードを収集ページに期待していたため、URL/CSV保存後にリスト解析へ移動して存在確認し、収集へ戻って後続の試験を行う。プロジェクト引継ぎと収集ページに解析ボタンがないことも確認する。既存のカード存在確認を削除せず、新導線で検証する。

ローカルの実DB付きE2E初回はwebServer起動待ち60秒でタイムアウトし、アサーションまで到達していない。専用 `_test` DBで再実行し、最終headのCIで全E2Eを確認する。

再実行ではページ復帰時に収集元が初期値へ戻るためURL入力が見つからず、テスト側で収集元を再選択する修正も追加した。最終的に `npx playwright test tests/workflow.spec.ts --timeout=180000` はPC・スマートフォンの2件成功（各36秒、全体1.9分）。専用 `leadhive_source_cleanup_test` DBのみ使用。型チェック・Lint・diff確認は成功。CIの全E2Eは別途実行中であり、このローカル2件成功と区別する。
