# 都道府県選択と全国の地域順検索

基準: main a172be612e89382f3147a92cc3ce57ce20234d03。

## 操作

企業収集の都道府県を「全国」または47都道府県から選択する。プロジェクト・Target Profileの検索キーワードは従来どおり初期表示し、開始前に編集できる。キーワードは1行に1件。保存済みの市町村・複数地域指定は、互換性のため既存値の選択肢として残す。

Google検索（Serper）の新規件数目標収集では、検索組み合わせのプレビューを表示する。全国は北海道、青森県、岩手県…沖縄県の順。各県内では全キーワードをfair-v1で検索し、新規候補が増えない連続ページ、ページ上限、検索エラー等による停止後に次の県へ進む。再試行待ちの県を飛ばして後の県へ進めない。

目標件数は全国の合計であり、県ごとの目標ではない。リクエスト上限は全県・全キーワード・ページ・再試行の合計（最大50）。上限・目標達成時は即停止する。47県を検索する保証はない。進捗に計画地域数・未検索地域数・継続地域を表示する。住所や業種の正しさは検索語だけでは確定しない。

## 互換性・安全

- APIの新規オプトイン `region_mode=prefecture_order`。従来は `literal`。
- 全国展開はSerperの件数目標収集のみ。他Sourceは従来の地域指定検索。定期収集も従来方式を維持する。
- 新方式は永続化された検索タスク・Raw Ledger・既存キャンセル/復旧/重複排除を再利用する。
- 既存のquery plan hashは変えない。旧ジョブへ全国展開を後付けしない。
- 新方式のみfair schedulerを使用する。従来ジョブのfeature flag設定は維持する。
- DB/migration変更なし。送信/承認ロジック変更なし。
- 実API検索、企業サイトアクセス、メール/フォーム送信は検証に使用しない。

## 検証

オフラインの実workerテストで、北海道の2キーワードが各2ページで停止後に青森県へ進むこと、6リクエスト上限で残りを検索しないこと、94タスクと未検索90タスクを記録することを確認する。47県の順序、単一県、旧hash互換、未対応source拒否のテストを追加。

Playwrightのdesktop/mobileで都道府県選択、北海道/沖縄県の組み合わせプレビュー、APIへのregion_modeと検索上限の引継ぎを検証する。通常の型検査/lint/buildとバックエンドのRuff/mypyも実行する。
