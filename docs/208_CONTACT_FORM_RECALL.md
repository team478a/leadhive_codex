# 問い合わせフォームの取りこぼし改善

## 目的

企業サイトに問い合わせフォームが存在するのに未発見と分類されるケースを減らし、未発見理由をログから可視化する。画面上の検出結果は送信許可を意味しない。

## 範囲と安全条件

- 静的HTMLのリンク探索・フォーム候補判定と、保存済み解析ログの診断を改善する。
- JavaScript描画フォームの実ブラウザ取得、AI判定、フォーム項目解析、送信・承認・CF7処理は対象外。
- robots、same-site、取得回数・時間上限、外部フォーム候補の上限を緩和しない。
- 診断・テストでは実サイトへのアクセス、AI呼び出し、フォーム送信を行わない。
- 実サイトでの改善比較は、田中さんの明示承認後に限る。

## 実装内容

### 探索・判定改善

- 直接問い合わせ、相談・見積、資料請求のリンク語を優先度分けし、NFKCと空白除去で表記揺れを吸収する。
- リンク本文に画像alt、title、aria-labelを加える。
- area[href]、静的なlocation代入、data-href、data-urlを探索する。
- 問い合わせURLの推測候補を拡張し、推測アクセスは1社あたり6件までに制限する。
- 実リンク先でフォームを確認した後は推測URLを試さない。
- 問い合わせ文脈での誤検出を抑え、メルマガ登録・予約などを候補から除外する。
- 解析版を2.3へ更新する。既存データは自動再解析しない。

### 未発見理由診断

- 一括再検出と同じ対象選択条件を共通化する。
- 最後の analysis_started 以降のログを、トップ取得失敗、取得上限、robots/転送、埋め込み未確認、独自入力欄、到達ページでフォームなし、推測URLのみ、問い合わせページ未到達、旧解析に分類する。
- 理由別件数、企業情報、副理由、最後に到達したURL、解析日時・版をページング表示し、CSV出力できるようにする。

## 比較再解析（未承認・未実施）

診断と探索改善のマージ後、理由別に最大50社を選んで再解析する比較工程は、明示承認があるまで実行しない。全体一括再解析も行わない。比較実施時は発見数、誤検出、人による確認結果、取得回数・時間を記録する。
